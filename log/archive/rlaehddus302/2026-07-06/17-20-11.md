## 큰 그림: 뭘 배워야 하는가

우리 시스템은 결국 **부품 3개를 API로 잇는 것**이에요. 그래서 배울 것도 딱 3덩어리입니다:

```
[기반 개념]  ← 전원 공통. 이거 없으면 대화 자체가 안 됨
    ↓
[부품 3개 각각 만져보기]  ← Mattermost / Hermes / Honcho
    ↓
[붙이기 = 우리가 만들 레이어]  ← 어댑터 + 팀 집계 + 권한
```

## 0단계 — 기반 개념 (전원 공통, 2~3일)

이건 누가 무슨 역할이든 다 알아야 하는 "공용어"예요. 깊게 말고 **감만** 잡으면 됩니다.

| 개념 | 한 줄 뜻 | 왜 필요한가 |
|---|---|---|
| **LLM / 토큰 / 컨텍스트 윈도우** | AI가 한 번에 읽을 수 있는 글의 양엔 한계가 있다 | 메모리를 왜 "요약·검색"하는지 이해하려면 필수 |
| **에이전트 & 툴 콜(function calling)** | AI가 대화만 하는 게 아니라 "도구를 직접 호출"해 일한다 | 기획서의 "파일 생성·수정"이 이 원리 |
| **REST API / WebSocket** | 프로그램끼리 대화하는 두 방식 (REST=요청-응답, WebSocket=계속 연결해 실시간 수신) | Mattermost랑 우리가 이걸로만 연결 |
| **JSON** | 프로그램끼리 주고받는 데이터 표기법 | API 다루면 매 순간 봄 |
| **봇 계정 / 웹훅(webhook)** | AI가 사람인 척 쓰는 메신저 계정 / 이벤트 생기면 알려주는 콜백 | `@ai` 멘션 처리의 핵심 |
| **프로세스 분리** | 우리 코드는 Mattermost 안에 넣지 않고 "옆에서 따로 도는 별도 프로그램" | ★라이선스(AGPL) 때문에 **반드시** 이래야 함 (PLAN 6-1) |
| **Docker / 컨테이너** | 프로그램을 설정까지 통째로 담은 "실행 상자" | 설치·배포가 전부 이걸로 됨 |

**추천 학습법**: 위 표를 그냥 이 폴더에서 Claude Code한테 하나씩 "이거 초등학생도 알게 설명해줘" 물어보세요. 여러분 워크플로 그대로고, 모르는 게 나오면 즉석에서 파고들 수 있어요.

## 1단계 — 부품 3개 직접 만져보기 (이번 주 핵심)

여기가 진짜예요. **전원이 셋 다 가볍게 한 번씩 돌려보고**, 그다음 각자 담당 부품을 깊게 파는 구조를 추천해요.

### 부품 A. Mattermost (담당: 김동연 / 인프라)
"우리가 만들 게 아니라 그냥 설치해서 쓰는 메신저"

1. Docker로 내 컴퓨터에 Mattermost 하나 띄우기 (공식 문서에 `docker` 한 줄 설치법 있음)
2. 팀 만들고 채널 만들고 그냥 카톡처럼 써보기
3. **봇 계정** 하나 만들고, 그 봇의 토큰(비밀번호 같은 열쇠)으로 REST API를 때려서 "채널에 메시지 보내기" 성공시키기
4. WebSocket에 연결해서 "누가 메시지 보내면 내 프로그램이 그걸 받는 것"까지 해보기
   → 여기까지 되면 `@ai 멘션 → 우리 코드가 수신` 왕복의 절반이 끝난 거예요.

### 부품 B. Hermes Agent (담당: 여운호 / AI 엔진)
"우리가 만들 게 아니라 포크해서 심장으로 쓰는 개인 AI 엔진"

1. GitHub에서 hermes-agent 클론(내 컴퓨터로 복사)해서 로컬에서 실행, AI랑 대화해보기
2. **메모리가 실제로 어디에 어떻게 저장되는지 파일/DB를 직접 열어보기** — 지난 대화에서 정리한 3층(영속 사실 로그 / SessionDB / 스킬)이 코드에서 실제로 어떻게 생겼는지 눈으로 확인
3. skill_manage로 AI가 스킬을 만들고 고치는 걸 관찰
   → 이게 7/09 일정의 "메모리 구조 학습"이고, 지난번 얘기한 **"1인용 → 팀용 변환"의 난이도를 여기서 판단**하게 돼요.

### 부품 C. Honcho (담당: 여운호+신홍재 / 팀 지능의 뿌리)
"Hermes가 기억·사용자모델링에 쓰는 하부 저장소. 팀 전환의 발판이 여기 있음"

1. Honcho 문서에서 **workspace / peer / session** 데이터 모델 파악
2. ★확인 1순위: "한 session에 여러 peer를 넣을 수 있나? peer별로 기억이 격리되나?" — 스키마를 직접 열어 확인
   → 지난번 말한 팀 매핑(`팀=workspace, 팀원=peer, 채널=session`)이 실제로 되는지가 여기서 판가름 나요.

## 2단계 — 붙이기 (담당: 신홍재 주도 / 전원 관여)

부품을 다 만져봤으면 이제 우리 오리지널 부분이에요. 개념적으로 배울 것:

- **어댑터 패턴** — "Mattermost 말투"와 "Hermes 말투"를 통역하는 중간 코드
- **개인 → 팀 집계** — 여러 사람 메모리를 합쳐서 "팀 뇌" 뷰 만들기
- **권한·비밀 필터** — 개인 메모리가 팀 공유로 올라갈 때 걸러내는 로직 (제일 어렵고 제일 novel)

이건 부품을 모르면 설계가 안 되니, **1단계 끝나기 전엔 손대지 마세요.** 8월 재결정 사항(PLAN Phase 8)이기도 하고요.
