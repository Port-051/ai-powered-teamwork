좋은 질문이고, 실제로 리셀러(재판매) 사업 구조를 정확히 알아야 하는 부분이라 짐작하지 않고 확인하겠습니다 — OpenRouter/Nous 같은 곳이 실제로 계정을 어떻게 운영하는지.





이제 정확한 그림이 나왔습니다. **"매번 계정을 새로 만든다"가 아니라, "1개(또는 소수)의 대형 계약 계정 뒤에서 여러 사용자를 내부적으로 나눠 관리한다"** 구조입니다.

## 실제 구조: 계정 1개 + 내부 사용자별 가상 키

```
사용자 A ──┐
사용자 B ──┼── [Nous Portal 자체 로그인] ── [Nous가 OpenRouter와 맺은 계약 계정 1개]
사용자 C ──┘         (사용자마다 다른               (Anthropic/OpenAI/Google API 키 1세트,
                      "가상 키"로 구분)                기업용 대량 계약)
```

핵심 개념은 **"Virtual Key"(가상 키)**입니다. 검색 결과 원문:

> **"Provider API keys themselves stay encrypted and are never exposed to end users. Platform teams issue distinct virtual keys per team, project, or customer"**

즉:

1. **Nous Research는 Anthropic/OpenAI/Google과 직접 계약하지 않고, OpenRouter라는 한 단계 더 도매상을 거칩니다** (지난번 확인한 그대로).
2. **OpenRouter가 Anthropic/OpenAI/Google 각각과 진짜 API 키를 딱 1세트씩(또는 기업용 대량 계약)** 맺습니다. 이건 일반 개인 가입이 아니라 **기업 대 기업 계약**입니다.
3. 사용자(Nous Portal 가입자, 우리 같은 Hermes 사용자)는 **그 진짜 키를 절대 못 보고, 자기만의 "가상 키"**를 받습니다. 이 가상 키는 실제로 Anthropic에 보내는 키가 아니라, **"이 요청은 누구 몫인지 장부에 기록하는 용도의 키"**입니다.
4. 실제 요청이 오면: 가상 키로 "누가 보냈는지" 확인 → 사용량 장부에 기록 → **뒤에서는 그 진짜(1개) API 키로 Anthropic/OpenAI에 실제 요청 전송** → 응답을 다시 그 사용자에게 돌려줌.

## 그래서 질문에 답하면

**"매번 새 계정을 만들어서 그 계정으로 키를 산다"는 게 아닙니다.** 정반대입니다:

- 새 사용자가 가입해도 Anthropic/OpenAI에 새 계정이 생기는 게 아니라, **그냥 하나의 큰 계약 계정 뒤에 사용자 하나가 장부상으로만 추가되는 것**입니다.
- 이렇게 하는 이유: (a) 기업 계약이라 일반 무료/개인 요금제보다 **훨씬 높은 처리량 한도**를 확보할 수 있고, (b) 계정을 여러 개 만드는 건 오히려 각 회사 약관 위반(다중계정 생성 금지)이라 **위험한 방법**이지, 정상적인 리셀러 사업 방식이 아닙니다.

## 우리 프로젝트에 적용하면

우리가 나중에 "매니지드 호스팅(유료 구독)" 사업모델로 갈 때도 같은 원리를 써야 합니다:

- ❌ 팀원마다 Anthropic 계정을 새로 만들어서 각자 키를 발급 → 번거롭고 확장 안 됨
- ✅ **우리가 Anthropic/OpenAI/Google과 사업자 명의로 API 키 1~소수 개를 계약하고, 우리 서버 안에서 "이 요청이 어느 팀/사용자 몫인지"를 우리 DB로 장부 관리** (지난번 얘기한 memory-provider의 `user_id` 태깅과 같은 원리)
