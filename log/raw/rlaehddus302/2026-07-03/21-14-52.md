## git 워크트리(worktree) 상세 설명

### 기본 개념

보통 git 저장소(레포)는 폴더 하나에 "지금 보고 있는 작업 상태"가 하나만 존재해요. 브랜치(branch, 독립된 작업 흐름의 갈래)를 바꾸면 `git checkout`/`git switch`로 폴더 안의 파일들이 그 브랜치 상태로 바뀌죠.

**워크트리**는 같은 저장소의 기록(커밋 히스토리)을 공유하면서, **다른 브랜치를 다른 폴더에 동시에 펼쳐놓는 기능**이에요. 즉:

```
team-work/
  ai-powered-teamwork/          ← 원래 폴더 (main 브랜치)
  ai-powered-teamwork-실험용/    ← 워크트리로 추가한 폴더 (다른 브랜치)
```

두 폴더 다 `.git` 기록은 공유하지만, 파일 상태는 서로 독립적이에요. 한쪽에서 파일을 고쳐도 다른 쪽엔 영향 없어요.

### 왜 쓰는가

- 지금 하던 작업(커밋 안 한 상태)을 그대로 둔 채로, 급한 다른 브랜치 작업을 바로 시작하고 싶을 때 (기존엔 `git stash`로 임시 저장해야 했음)
- 여러 작업을 동시에 병행하면서 서로 파일이 안 섞이게 하고 싶을 때
- Claude 같은 AI 에이전트가 여러 작업을 병렬로 돌릴 때, 서로 다른 워크트리에서 작업하면 파일 충돌 없이 동시에 진행 가능

### 기본 명령어

```
git worktree add ../실험용-폴더 새브랜치이름     # 새 워크트리 생성 + 새 브랜치
git worktree list                              # 현재 워크트리 목록 보기
git worktree remove ../실험용-폴더              # 워크트리 제거
```

### 왜 우리 프로젝트에서는 안 쓰는가

이 레포의 CLAUDE.md 가이드에는 이렇게 정해져 있어요:

> "이 팀은... '이 폴더에서 Claude Code를 켜고 작업하는 것'만 협업 방식으로 쓴다... 워크트리 같은 고급 기능이 실패하거나 이 프로젝트 규모에 안 맞아 보이면, 조용히 우회한다."

이유는:
1. 팀원 대부분이 git 경험이 적어서, 폴더가 여러 개로 나뉘면 "지금 내가 어느 폴더에서 작업 중인지" 헷갈리기 쉬움
2. 이 프로젝트는 규모가 작아서 동시에 여러 브랜치를 병행할 필요가 거의 없음
3. `log/raw` 자동 push 훅 등도 "이 폴더" 기준으로 동작하게 짜여 있어서, 워크트리로 폴더가 분산되면 로그 자동화가 꼬일 수 있음

그래서 실제로 이 레포에서 작업할 때는 지금 이 폴더 하나에서 브랜치를 바꿔가며(또는 그냥 순차적으로) 작업하는 게 맞고, 워크트리는 필요 없다고 보시면 됩니다.
