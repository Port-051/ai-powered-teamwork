- git 워크트리는 쓰지 않는다. stash로 충분하고, 팀원 대부분 git 경험이 적어 폴더가 여러 개로 나뉘면 혼란만 커진다는 판단.
- `submission/기획서_TeamBrain_Port051.docx` 작업 시 `submission/reference/기획서_원본양식.docx`(SW Maestro 17기 제출 양식 원본)를 절대 수정하지 않는 비교 기준 파일로 둔다. 문서에서 파란 글씨는 "수정 필요(채워 넣을 자리)", 검은 글씨는 "수정 금지(그대로 유지)"를 의미하므로 이 규칙을 지켜서 채운다.
- 목차(TOC)는 새로 만들지 않고 원본 양식 파일의 목차 표 XML을 그대로 복사해서 쓴다 — 직접 재구성하면 서식이 계속 원본과 어긋남.
- 모든 표에 행 분할 방지(cantSplit) 옵션을 적용해 표가 페이지 경계에서 잘리지 않게 한다.

- **PLAN.md에 "팀 협업 지능 레이어" 상세 설계 확정 (Phase 4-1 신설, unhoyeo가 반영/커밋).** 이게 프로젝트의 유일한 오리지널 IP라 구체화함:
  - 데이터 흐름 4단계: 캡처(Mattermost 이벤트) → 추출·정제(지식 단위로 가공) → 저장·색인(임베딩 + 메타데이터) → 검색·주입(다음 `@ai` 호출 시 컨텍스트로 반영).
  - **지식 단위(Knowledge Unit) 종류**: 결정(Decision) / 사실·노하우(Fact) / 미해결 이슈(OpenQuestion) / 용어(Glossary). 각 단위는 출처 스레드·채널·작성자·타임스탬프·신뢰도를 메타데이터로 가짐.

  - **개인 DM 대화는 팀 지식으로 승격하지 않는다 — 공개 채널 대화만 팀 지식 후보** (권한/비밀정보 관리 원칙과 일치).
