## 1. API를 직접 호출하면 대화 기록 관리를 내가 해야 하나?

**네, 맞습니다.** API를 그냥 raw하게 호출하는 코드를 직접 짜면(예를 들어 지난번 실습 폴더의 `bot.py`처럼), **"이전 대화를 저장해뒀다가 다음 호출에 다시 붙여 보내는" 그 역할을 개발자인 내가 코드로 직접 구현해야 합니다.**

- **claude.ai 웹, ChatGPT 웹, Claude Code CLI** — 이런 "완성된 앱"들은 그 앱 자체가 뒤에서 대화 기록을 저장하고 매번 다시 붙여 보내는 걸 사용자 눈에 안 보이게 대신 해줍니다. 사용자는 그냥 채팅하듯 쓰면 됨.
- **API를 직접 호출하는 내 코드** — 이건 그런 "앱"이 없는 맨몸 상태라, `messages` 배열에 이전 대화를 계속 쌓아서 넘기는 로직, 어디에 저장할지(파일? DB?), 언제 요약할지, 컨텍스트 창 넘으면 어떻게 자를지 — 이런 걸 전부 직접 짜야 합니다.
- **Hermes** — 이게 정확히 이 "번거로운 부분을 대신 해주는 앱" 역할입니다. Hermes CLI로 대화하면, `state.db`에 저장하고 다음 호출에 다시 붙여 보내는 걸 Hermes가 알아서 처리해줍니다. 그래서 지난번에 "Hermes는 기억을 관리해주는 엔진"이라고 한 게 바로 이 부분이고, 우리 프로젝트가 이걸 직접 안 만들고 Hermes를 가져다 쓰려는 이유이기도 합니다.

## 2. 같은 컴퓨터에 PowerShell과 WSL에 동시에 설치해도 되나?

**문제없습니다.** 둘은 완전히 분리된 환경(별도 파일시스템, 별도 설정 폴더)이라 서로 충돌하지 않습니다. 다만 딱 하나 주의할 점:

- 만약 **양쪽 다 동시에 같은 슬랙 워크스페이스/봇 토큰으로 게이트웨이를 띄워서 돌리면**, 멘션 하나에 응답이 두 번 오는 것처럼 헷갈릴 수 있습니다. (같은 봇이 PowerShell 쪽과 WSL 쪽에서 동시에 듣고 있는 셈이라서)
- 그냥 CLI로 혼자 대화하거나, 서로 다른 용도/워크스페이스로 쓰면 전혀 문제 없습니다.

정리하면: 설치 자체는 둘 다 있어도 무해하고, 실제로 게이트웨이(메신저 연동)를 **동시에 둘 다 켜두는 것만** 피하면 됩니다.
