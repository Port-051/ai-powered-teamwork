  When gateway.multiplex_profiles is on, the default gateway is the
  single inbound process for every profile. Starting a separate
  gateway for this profile would double-bind its platforms (two
  pollers on one bot token, port conflicts).

  Manage the multiplexer instead (from the default profile):

**무슨 뜻이냐면**: default profile의 게이트웨이가 이미 멀티플렉서로 켜져 있어서, `second` profile을 포함한 모든 profile의 메신저 연결을 그 안에서 대신 서빙하고 있습니다. 그런데 `second` 것만 따로 또 켜려고 하면 같은 봇 토큰을 두 프로세스가 동시에 붙잡으려는 꼴이 돼서(이중 폴링, 포트 충돌) 막아준 겁니다.

**해야 할 일**: `second` profile을 따로 켜지 말고, **default profile의 게이트웨이만 재시작**하면 됩니다:
```bash
hermes gateway run
```
(또는 이미 tmux로 돌리고 있다면 그 세션 안에서 재시작 — Ctrl-C 후 다시 `hermes gateway run`)

**주의**: 메시지 마지막에 `--force`로 강제로 별도 프로세스를 띄우는 옵션도 있다고 나오는데, 멀티플렉서가 켜져 있는 동안엔 쓰지 마세요 — 토큰 충돌 나서 둘 다 제대로 안 돌아갈 수 있습니다.
