네, 있습니다. 아까 두 번째 선택지로 제가 GitHub CLI(`gh`)를 언급했었는데, 그게 WSL에서 GCM이랑 거의 똑같은 역할을 합니다.

**`gh auth login`** 이 그 방법이에요:
1. `gh` 설치 (`sudo apt install gh`)
2. `gh auth login` 실행 → "브라우저로 로그인할지" 물어봄 → 선택하면 코드 하나를 보여주고 브라우저가 열림
3. 브라우저에서 GitHub 로그인 + 승인만 하면 끝. 토큰을 사람이 직접 복사해서 붙여넣을 필요가 없고, `gh`가 알아서 발급받아 안전하게 저장하고, git push/pull에도 자동 연동됩니다.

이게 아까 제가 처음 물어봤을 때 "추천"으로 걸어뒀던 옵션이었어요 — 토큰을 채팅창에 직접 붙여넣는 것보다 이 방식이 더 안전합니다 (토큰 원문이 대화 기록에 남지 않으니까요).

지금이라도 이 방식으로 바꾸고, 아까 채팅에 노출된 토큰은 폐기하는 게 좋습니다. 진행할까요?

완료되면 알려주세요. 그러면 제가 기존 토큰 방식(`~/.git-credentials`)을 지우고, push/pull이 gh 인증으로 잘 되는지 확인하겠습니다. 그 다음 아까 노출됐던 토큰도 GitHub에서 폐기(revoke)하시길 권장드려요 (Settings → Developer settings → Personal access tokens에서 삭제).
