확인해봤습니다. 사용자가 기억하시는 게 있긴 합니다 — 근데 그건 "Mattermost 같은 외부 서비스를 검색하는 기능"이 아니라 완전히 다른 겁니다.

`hermes_cli/memory_providers.py`를 보면 **"memory provider"**라는 게 있는데, 이건 **Hermes 자신의 장기기억을 어디에 저장할지 고르는 설정**입니다:

```python
MEMORY_PROVIDERS = {
    "hindsight": HINDSIGHT,  # 외부 클라우드/자체호스팅 벡터 기억 서비스
}
```

- 기본값은 `builtin` (로컬 SQLite — 지금까지 계속 얘기해온 `session_search`가 뒤지는 그 DB)
- 대신 `hindsight`라는 외부 서비스(Vectorize의 클라우드 API 또는 자체 호스팅 인스턴스)로 **"기억을 어디에 저장하고 불러올지"를 바꿔 끼울 수 있는** 설정입니다.

즉 이건 **"Hermes가 나눈 대화를 어디에 저장할까"**를 다루는 것이지, **"Mattermost 서버 안의 데이터를 검색해올까"**와는 완전히 다른 문제입니다. 비유하면:

- **memory provider** = 내 다이어리(Hermes 기억)를 종이 노트에 쓸지 클라우드 노트 앱에 쓸지 고르는 것
- 우리가 필요한 것 = 다른 사람(Mattermost)의 서랍(DB) 안에 있는 걸 찾아와서 읽는 것

전혀 다른 기능이라서, 여기다 Mattermost 검색을 붙일 수는 없습니다. `mode: local_external`로 Hindsight를 자체 호스팅하는 옵션이 있긴 하지만, 그것도 "기억 저장소 종류"를 바꾸는 것이지 임의의 외부 API(Mattermost REST API)를 호출하게 해주는 범용 확장점이 아닙니다.

**결론은 그대로 MCP입니다.** "외부 도구/데이터를 대화 중에 스스로 불러쓰게 하는" 공식 확장점은 `mcp_servers`(`tools/mcp_tool.py`)이고, memory provider는 그 목적을 위한 자리가 아닙니다.
