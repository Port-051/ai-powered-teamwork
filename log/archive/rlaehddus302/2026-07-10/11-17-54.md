### user
아니 저렇게 멀티플렉싱을 설정한다고 치고 그 다음에 각 프로파일 설정은 어떻게 하라는 거지?

### assistant














멀티플렉싱은 그냥 "여러 프로세스 대신 하나로 합쳐서 서빙하는 방식"을 켜는 스위치일 뿐이고, **profile 자체를 만들고 설정하는 절차는 그대로**입니다. 순서는 이렇습니다.

**1. profile 만들기 (팀원 수만큼)**
```bash
hermes profile create dongyeon
hermes profile create unho
hermes profile create hongjae
```

**2. 각 profile 기본 설정 (모델/API 키)**
```bash
dongyeon setup
unho setup
hongjae setup
```

**3. 각 profile의 `.env`에 Mattermost 봇 토큰 넣기**
```bash
# ~/.hermes/profiles/dongyeon/.env
MATTERMOST_URL=https://<mattermost-주소>
MATTERMOST_TOKEN=<dongyeon용 봇 토큰>       # 반드시 profile마다 다른 토큰
MATTERMOST_ALLOWED_USERS=<동연님 User ID>
```
같은 토큰을 두 profile이 쓰면 시작 시 충돌 에러가 남 — Mattermost 봇 계정을 사람 수만큼 따로 만들어야 하는 이유입니다(이건 지난번 답변의 2단계 그대로).

**4. 각 profile의 `config.yaml`에서 Mattermost 어댑터를 켜기**
Mattermost는 WebSocket(아웃바운드) 방식이라 port-binding 플랫폼 목록(`webhook`, `api_server` 등)에 안 들어가기 때문에, 멀티플렉싱 모드에서도 이 설정은 **각 secondary profile에 그대로 넣어도 됨** — default profile에만 몰아 넣지 않아도 됩니다.

**5. 마지막에 default profile에서 멀티플렉싱 스위치만 켜기**
```bash
hermes config set gateway.multiplex_profiles true
hermes gateway restart      # default 게이트웨이만 재시작
```
→ 이제 default 게이트웨이 하나가 dongyeon/unho/hongjae 세 profile의 Mattermost 어댑터를 각자 자기 `.env`/토큰으로 다 띄워서 서빙합니다.

**주의**: 이 상태에서 `dongyeon gateway start`처럼 개별 profile로 따로 게이트웨이를 켜면 안 됩니다 — "이미 멀티플렉서가 서빙 중"이라는 에러가 납니다. profile 설정(.env, config.yaml, SOUL.md)을 바꾼 뒤에는 개별 재시작이 아니라 `hermes gateway restart`(default)로 전체를 다시 띄워야 반영됩니다.
