## 1. 심야: 로컬 Mattermost 실서비스 띄우기 + 아키텍처 이해 (00~02시)
- **Docker Mattermost + ngrok 터널로 팀원 실접속 성공**: WSL 안에 CLI Docker로 Mattermost(+Postgres) 컨테이너를 띄우고, ngrok(무료, authtoken 등록) 터널로 공개 URL을 만들어 팀원이 접속. 처음엔 `SITEURL=http://localhost:8065` 때문에 로그인/쿠키가 꼬였고, 서버 안에서 관리자 계정(`shj5771`, system_admin) 비밀번호를 직접 재설정해서 해결. **팀원이 `test_shj` 계정으로 실제 로그인해 대화(총 8개 메시지)까지 성공** — Mattermost→Postgres `posts` 테이블에 순정 그대로 대화가 쌓이는 구조를 눈으로 확인.
- **비용 확인**: Docker·ngrok 둘 다 현 단계(테스트)에선 0원. ngrok 무료는 URL이 매번 바뀌고 컴퓨터/터널이 켜져 있을 때만 유효 — 상시 서비스엔 부적합.
- **DB 구조 학습**: Mattermost는 자체 DB 엔진이 없고 Postgres/MySQL을 필수로 "빌려" 씀. DM이든 공개채널이든 전부 같은 `posts` 테이블에 평문 저장(`type` O=공개/P=비공개/D=DM/G=그룹DM으로 구분). 회사 MySQL로도 연결 가능하나 반드시 빈 전용 스키마여야 함(이름 충돌 시 지저분하게 실패).
- **프라이버시 관련 핵심 인사이트**(팀 공유 성격): ① DB 접근 권한이 있는 **관리자는 마음먹으면 DM 포함 모든 메시지를 볼 수 있음** — "데이터 주권"은 "외부 벤더가 못 본다"는 뜻이지 "그 조직 관리자도 못 본다"가 아님. "DM 절대 안전"으로 마케팅하면 과장. ② 팀 지능 레이어는 DM만 막을 게 아니라 **채널 공개 범위(공개/비공개/DM/그룹DM) 기준으로 지식 편입 여부를 결정하고, 원본 채널 멤버십을 그대로 상속**해서 검색 답변에 노출해야 함(비멤버에게 새 구멍이 생기지 않도록). ③ 진짜 어려운 본체는 권한 필터가 아니라 (1) 요약/추출 품질 (2) 검색/응답 품질 (3) PMF (4) 개인↔팀 브릿지. MVP에선 임베딩/검색을 아예 생략하고 "요약 문서 전체를 매번 컨텍스트에 주입"하는 초안 E 방향도 논의(→ 학습 노트로 experiments 폴더에 기록).

서브에이전트(fork)로 소스를 스크래치패드에 얕게 클론해 읽고, 결과를 `experiments/hermes-mattermost/2026-07-08/hongjae/`에 커밋.
- **`mattermost-source-analysis.md`**: 플러그인(hooks.go, 40+훅)은 서버 프로세스 내장이라 AGPL 파생저작물 리스크 — CLAUDE.md의 "플러그인 금지"를 소스 레벨에서 재확인. REST v4/WebSocket(`posted` 이벤트로 폴링 없이 실시간 수집)은 완전 분리 프로세스라 우리 원칙과 일치. 채널 타입(D/G vs O/P)을 프라이버시 필터 1차 신호로, 채널 멤버십을 접근제어로 그대로 상속 가능(재구현 불필요). 이후 "0. 레포 전체 구조"(webapp/모바일/e2e는 안 봐도 됨, `server/public`이 핵심, 나중엔 코드 대신 공식 OpenAPI 문서 참고) 섹션 추가.
- **`hermes-source-analysis.md`**: **메모리 Provider 인터페이스(`agent/memory_provider.py`)가 코드 수정 없이 꽂을 수 있는 공식 확장점** — `prefetch`(턴 시작 전 팀지식 주입)/`sync_turn`(턴 종료 후 저장·판별)이 정확히 우리가 필요한 지점. Mattermost 어댑터는 이미 완성(1,281줄)이라 A안(Hermes 확장)이 B안(직접 어댑터)보다 코드 레벨로 현실적. 단, **외부 메모리 provider는 프로세스당 하나만** 허용(Honcho와 동시 사용 불가). 세션 키는 `platform:chat_id`라 "팀" 개념이 없음 — 코어 포크는 비추천.
- 레이어 없이 Hermes+Mattermost만 연결하면 "채널별로 따로 노는 개인 봇 여러 개"가 됨을 확인 — 방 단위 격리를 넘어 지식을 엮는 게 우리 레이어(①)의 존재 이유. 두 구조도(레이어 전/후)를 만들어 캡처 이미지 1개를 `shared` 폴더에 커밋(HTML 2개는 삭제).
