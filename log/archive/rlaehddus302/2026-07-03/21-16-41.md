기존에 commit 안 하고 branch로 넘어가면 git stash로 해서 귀찮았는데 좋네. 그럼 git stash는 이제 쓸 필요가 없나?

### assistant
## git stash가 여전히 유용한 경우

워크트리가 "동시에 여러 폴더에서 작업"을 해결해준다면, stash는 **"이 폴더, 이 브랜치에서 잠깐 변경사항을 치워두고 싶을 때"** 여전히 유용해요. 완전히 대체되는 건 아니에요.

**stash가 더 편한 경우:**
- 같은 브랜치 안에서 "이 실험적인 수정 잠깐 빼고 원래 상태로 돌아가서 확인해보고 싶다" 할 때 — 굳이 폴더를 새로 만들 필요 없이 `git stash` → 확인 → `git stash pop`으로 끝
- pull(원격 저장소의 최신 기록을 받아오는 것) 하기 전에 로컬의 자잘한 수정을 잠깐 치워야 할 때
- 폴더를 하나 더 만들기엔 너무 사소한, 순간적인 전환일 때

**워크트리가 더 편한 경우:**
- 다른 브랜치에서 꽤 오래(몇 시간~며칠) 작업할 거고, 원래 작업 폴더도 그대로 살아있어야 할 때
- 두 작업을 왔다갔다 자주 전환하면서 동시에 진행할 때 (매번 stash push/pop 하는 게 오히려 더 번거로움)

정리하면: **짧고 같은 폴더 안에서의 전환 → stash**, **길고 폴더를 분리하고 싶은 병행 작업 → 워크트리**. 다만 이 프로젝트는 위에서 말씀드린 이유로 워크트리는 안 쓰기로 되어 있으니, 필요하면 stash를 계속 쓰시면 돼요.
