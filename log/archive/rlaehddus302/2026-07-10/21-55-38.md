### user
없는데 지금 docker에서 돌아가는 컨테이너가 없는데 뭐가 8065포트를 쓴다는 거지?

### assistant


도커 컨테이너가 안 떠 있다면 두 가지 가능성이 있다:

1. **Docker Desktop 자체의 네트워크 프록시 프로세스**(`com.docker.backend.exe`나 `vpnkit` 같은 것)가 이전 컨테이너 종료 후에도 포트를 완전히 안 놓아준 경우 — 흔히 있는 도커 버그
2. **Windows에서 도커랑 상관없는 다른 프로그램**이 우연히 8065 포트를 쓰고 있는 경우

이건 WSL 안이 아니라 **Windows 쪽**에서 확인해야 한다. Windows PowerShell(또는 cmd)을 열어서 아래 명령을 실행해줄 수 있나?

```
netstat -ano | findstr :8065
```

결과에 맨 끝 숫자(PID)가 나올 텐데, 그 PID로 어떤 프로그램인지 확인하려면:

```
tasklist /FI "PID eq <위에서 나온 숫자>"
```

이 두 결과를 알려주면 그게 Docker Desktop 관련 프로세스인지, 아니면 전혀 다른 프로그램인지 보고 어떻게 정리할지 알려줄게. 참고로 안 되면 Docker Desktop을 완전히 재시작(Quit → 다시 실행)하는 것만으로도 이런 유령 포트 점유는 대부분 풀린다.
