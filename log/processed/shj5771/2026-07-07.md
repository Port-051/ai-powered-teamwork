## Hermes ↔ Slack PoC 셋업 가이드 정리 — 팀 공유
- Mattermost 서버가 아직 없어서, Hermes 엔진 동작 자체를 먼저 확인하려고 임시로 Slack에 붙여 PoC 진행(데이터주권 차별점과는 별개인 "실험용"이며 최종 제품은 Mattermost라는 점을 명확히 함).
- 겪은 막힘 지점과 원인:
  - Slack Bot Token Scopes를 안 채우고 앱 설치하면 봇 토큰(`xoxb-`)이 아니라 사용자 토큰(`xoxe.xoxp-`)만 나온다. 최소 `app_mentions:read`, `chat:write` + 채널/DM 조회용 `channels:read`, `groups:read`, `mpim:read`, `im:read` 필요.
  - Event Subscriptions에서 `app_mention` bot event를 구독 안 하면, Socket Mode 연결은 성공해도 멘션 이벤트 자체가 안 들어와서 봇이 무응답(Bot Token Scope와 Event Subscription은 서로 별개 설정이라는 점 확인).
  - 모델 호출 결제 문제: OpenRouter로 유료 모델(claude-sonnet-5)을 쓰면 402(크레딧 부족) 에러. Claude 구독을 `hermes setup model`에서 "Claude Code" OAuth 로그인으로 연결해도, 서드파티 앱(Hermes) 호출은 구독 기본 한도가 아니라 별도 "extra usage" 결제가 필요해서 여전히 막힘. Nous Portal 무료 크레딧도 카드 등록을 요구해서 보류. 최종적으로 **OpenRouter의 무료 모델(`nvidia/nemotron-3-super-120b-a12b:free`)**로 맞춰서 결제 없이 해결.
- 위 시행착오를 반영해 "한 번에 되는 순서" 7단계를 `experiments/hermes-slack/2026-07-07/hongjae/GUIDE.md`로 정리해 커밋·푸시함:
  1. 토큰은 Claude Code 대화창에 절대 붙여넣지 않기(로그 자동 push 정책 때문에 GitHub에 노출될 수 있음)
  2. Hermes 설치 스크립트로 설치(레포 안에 Hermes 소스 넣지 않음)
  3. Slack 앱은 `slack-manifest.json`으로 한 번에 생성(스코프·이벤트·Socket Mode 누락 방지)
  4. App-Level 토큰(`xapp-`, scope `connections:write`), Bot 토큰(`xoxb-`) 2개 발급
  5. `hermes setup gateway`로 토큰 등록, systemd 서비스로 설치(터미널 꺼도 유지)
  6. 모델 provider 설정(무료 옵션은 "선택지 중 하나"로만 언급 — 비용/무료 여부를 과도하게 강조하지 않기로 함)
  7. `hermes gateway status` / `journalctl` / `agent.log`로 트러블슈팅 + "이건 임시 실습, 최종은 Mattermost"라는 주석
- 개인별 삽질 기록은 `hongjae/SETUP.md`(신홍재)로 별도 보관. 여운호가 먼저 겪은 절차(`unho/`)와 비교해 본질적으로 동일한 방식임을 확인(다만 여운호 쪽은 이미 무료/저비용 provider가 붙어 있어서 결제 이슈를 안 겪었던 것으로 추정).

## Hermes가 실제로 해주는 일 정리 — 팀 공유
- `experiments/hermes-slack/2026-07-07/hongjae/HERMES_ROLE.md`로 정리해 커밋·푸시.
- Hermes 역할은 크게 두 축: ①비서 기능(질문답변/웹검색/코드/파일/일정 등 즉석 작업) ②개인 학습·기억 기능(세션 넘어서는 영속 기억, Honcho 기반 사용자 모델링, 스킬 자동 생성, 세션 검색 FTS5).
- **지금 Slack PoC의 Hermes 봇은 "팀 공유 지능"이 전혀 구현돼 있지 않음** — 개인별로 따로 기억·학습할 뿐 팀원 간 지식을 엮어주지 않는다. 그건 PLAN.md 아키텍처의 ①②③(어댑터/팀 공유 지능 레이어/개인-팀 접합) 몫으로, 우리 프로젝트가 별도로 만들어야 함(8월 재설계 대상, 아직 손 안 댐).
- Slack 봇이 볼 수 있는 범위 확인: 지금 세팅은 자신에게 멘션되거나 DM으로 직접 받은 메시지만 수신. **다른 팀원들끼리의 DM은 봇 권한을 아무리 넓혀도 구조적으로 절대 못 봄**(Slack 자체 제약, 스코프 문제 아님). 채널(그룹) 전체 대화를 멘션 없이 다 보려면 `message.channels`/`message.groups` 이벤트 + `channels:history`/`groups:history` 스코프를 추가로 켜야 하고, 이 경우 **팀원 동의가 필요**하다는 점도 짚음.

## 팀 협업 인텔리전스 레이어 파이프라인 구체화 — 팀 공유
- PLAN.md Phase 8(8월 재설계 예정)을 당겨서 신홍재가 방향을 미리 스케치(아직 PLAN.md에는 반영 안 함, 대화 기록으로만 존재).
- 큰 트레이드오프: "원문 그대로 저장 후 검색(RAG)" vs "실시간 요약·구조화 축적" — 후자를 추천(원문 그대로면 검색 노이즈/품질 문제가 크고, "결정·노하우를 구조화해서 아는 것" 자체가 TeamBrain 차별점이기 때문).
- 5단계 파이프라인 뼈대(2026-07-06 decisions.md의 4단계 캡처→추출→저장→검색 모델을 더 세분화한 버전):
  1. **수집(Ingest)** — 봇이 초대된 모든 채널 메시지 수신(멘션 무관), 스레드 단위로 묶어 처리
  2. **선별(Filter/Classify)** — 저비용 모델로 "결정/노하우/사실" vs "잡담" 1차 분류, 잡담은 버림
  3. **추출(Extract)** — 통과분을 `{유형, 요약, 참여자, 채널, 원본 링크, 시각}` 구조로 정리 = 팀 지식 최소 단위
  4. **저장(Store)** — 임베딩 붙여 벡터 검색 저장소에 축적. "개인 vs 팀 공유" 권한 태그 필요(기본값 팀 공유, 명시적으로 "개인만"이라 표시한 것만 제외)
  5. **검색/응답(Retrieve)** — 각 팀원의 Hermes가 질문받으면 개인 기억 + 이 팀 공유 저장소를 함께 검색해 답에 반영(우리 코드가 이 검색을 Hermes에 tool로 노출)
- 남은 미해결 결정 사항(Phase 8에서 정할 것): ①실시간 처리 vs 배치(예: 매일 밤 일괄 정리) — 실시간이 체감가치는 크지만 비용/복잡도가 올라감. ②권한 태깅을 자동(민감해 보이면 자동 제외)으로 할지 vs 사용자가 수동으로 표시하게 할지.
- 임베딩 모델 후보 논의: 한국어 검색용으로는 KoBERT보다 **KR-SBERT / ko-sroberta**(문장 유사도용 추가학습 버전) 또는 다국어 **multilingual-e5, voyage-3**가 더 적합하다는 의견. 다만 현재(요약축적형 MVP) 단계에선 임베딩 검색 자체가 아직 불필요하다는 점도 확인.
