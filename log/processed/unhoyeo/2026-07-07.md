- 슬랙 앱은 Hermes 내장 manifest 생성기로 한 번에 생성(Socket Mode 포함) → `SLACK_BOT_TOKEN`/`SLACK_APP_TOKEN`을 `~/.hermes/.env`에 넣기만 하면 별도 설정 없이 자동 활성화됨을 확인.
- 게이트웨이 실행 후 `@teambrain_hermes` 봇이 Port_051 워크스페이스에 연결 성공, 멘션 시 스레드로 대화 이어짐. 슬래시 커맨드(`/hermes`, `/new` 등 49개)도 정상 등록됨.
- **로컬 실습의 구조적 한계 확인**: 게이트웨이는 맥북이 실행 중이고 네트워크가 살아있어야만 동작 — 맥북을 덮거나(절전) 와이파이가 끊기면 상시 서비스 등록(`hermes gateway install`)을 해둬도 함께 죽는다. → 8월 MVP는 로컬이 아니라 항상 켜져 있는 서버가 필요하다는 점을 재확인 (PLAN Phase 4 운영·배포와 연결).

## 로컬 Docker Mattermost 실습 + 아키텍처 재검토 필요 — 팀 공유
- Docker Compose로 로컬에 Mattermost(Team Edition) + Postgres를 띄워 Hermes와 연동하는 실습 진행. Apple Silicon에서는 공식 이미지가 arm64 미지원이라 `platform: linux/amd64`(로제타 에뮬레이션) 필요(리소스 부담은 크지 않음, 실측 0.5% CPU/475MiB RAM).
- 가입 화면이 `/preparing-workspace`로 무한 리다이렉트되는 버그를 겪음 — 원인은 기존 Docker volume 잔여 상태 + 체험판 라이선스 온보딩 단계 충돌. `docker compose down -v`로 볼륨 초기화 + `MM_SERVICESETTINGS_ENABLEONBOARDINGFLOW: "false"`로 온보딩 스킵하여 해결(다음에 같은 문제 겪을 사람을 위해 기록).
- 봇 계정 토큰을 `.env`에 붙여넣을 때 앞뒤 공백이 섞이면 인증 실패(`session_expired` 에러) — 토큰 값을 대화창에 노출하지 않고 텍스트 에디터에서 공백만 확인/제거하는 방식으로 해결.
- **중요 발견**: Hermes에 Mattermost 어댑터가 이미 내장되어 있어서, PLAN.md가 상정한 "① Mattermost 어댑터"를 처음부터 새로 만들 필요가 없어 보임 — 우리가 실제로 새로 짜야 하는 건 여전히 ②(팀 공유 지능 레이어)와 ③(개인-팀 지식 브릿지). 아키텍처/일정 계획에 반영 검토 필요.
- **인프라 관련**: 07/05에 있던 팀 호스팅 서버가 현재 내려가 있는 상태로 확인됨 — 8/16 MVP 목표에는 로컬 Docker가 아닌 별도 상시 호스팅 서버가 필요.
- 실습 결과(docker-compose.yml, 막힌 점/배운 점)는 `experiments/hermes-mattermost/2026-07-07/shared/NOTES.md`에 정리해 커밋함.

## PLAN.md 보강 — 타겟팅/차별점 + 핵심 기술 챌린지 — 팀 공유
- 오후 자체 논의(슬랙 대비 경쟁 시나리오, 타겟 시장)와 저녁 최학열 멘토 정규 멘토링 내용을 종합해 PLAN.md를 두 커밋으로 보강.
- **1차 베타 타겟 및 GTM(Phase 2-1, 2-2 신설)**: 자체 메신저 없이 카카오톡으로만 소통하는 중소기업(연구실·로펌·병원·제조업 등 보안·기밀에 민감한 조직) 우선 — 메신저 교체가 아니라 "신규 도입"이라 저항이 적다는 논리. GTM 순서 후보(①소마 내부팀 검증 → ②B2B 파일럿 → ③오픈소스 GitHub star)는 **아직 미확정**, 검토 방향으로만 기록.
- **슬랙 대비 방어선(Phase 5)**: 슬랙이 아이디어를 따라 만들어도 넘기 어려운 두 지점 — ①온프레미스(자체 서버, 슬랙은 클라우드 SaaS가 사업 본체라 못 따라옴), ②개인 프라이버시 필터(회사는 통제하고 싶고 직원은 반대 — 슬랙은 양쪽 다 만족 못 시킴).
- **핵심 기술 챌린지(Phase 4-1 신설)**: "팀 공유 지능 레이어"를 `필터(전처리) → 지식 엔진 → 답변 생성기` 3단계 파이프라인으로 구체화.
  - 프라이버시 필터: 1차(룰 베이스, 룰 정의 방식은 트리 구조 등 미정) + 2차(AI 컨텍스트 기반) 판별기. LLM 직접 판단은 비용(토큰)·정확도 부담이 커서 인코더 기반 경량 분류기(BERT류)를 대안으로 검토 중. 검증에는 개인챗/팀챗/애매한 회색지대챗 가상 데이터셋 + 판별 지표 필요.
  - 지식 체계화 엔진: 비정형 멀티턴 대화를 구조화하는 문제. 기업·업무마다 컨텍스트가 달라 일반화가 어려움 — 1:1 스레드 등 한 가지 형태부터 먼저 검증하는 방향. 참고 사례로 LLM 메모리 압축 방식, 팔란티어식 온톨로지 언급.
  - 자체 디코더를 직접 만들어야 할 가능성도 논의됐으나 미확정.
- 저녁 멘토링 회의록 전체는 `meetings/2026-07-07_최학열-멘토링.md`로 별도 저장(네이버 사내 와이파이 감사실 사례로 프라이버시 필터 필요성 뒷받침, "AI 관심 스타트업" 타겟 후보 - 기존 "메신저 없는 중소기업" 타겟과는 다른 축이라 조율 필요, 매니저용 "휴먼 오케스트레이션" 아이디어 등 포함).
