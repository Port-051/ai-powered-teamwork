**Hermes 정체 확인:** PLAN.md에서 말하는 Hermes는 **NousResearch/hermes-agent** (MIT, CLI 기반, 세션 간 기억·스킬 자동 생성·멀티플랫폼 게이트웨이를 갖춘 자기개선형 AI 에이전트)입니다. `unho`님 실습 폴더에 이미 `hermes doctor`, `hermes gateway run` 같은 명령이 나오는 걸 보니 이미 로컬에 설치까지 되어 있는 상태네요.

**접근 순서 추천:**

1. **개념부터 (30분)** — 공식 문서(https://hermes-agent.nousresearch.com/docs/) 중 "Overview"와 "Memory" 섹션만 먼저 읽기. 코드 이해가 아니라 "메모리가 세션 간에 어떻게 유지되는지" 감만 잡으면 됨. 우리 프로젝트에서 Hermes가 맡는 역할은 딱 하나 — **개인 학습·기억**(PLAN.md Phase 4의 ③번 박스) — 이므로 스킬 자동생성이나 멀티플랫폼 연동 같은 나머지 기능은 지금 단계에선 몰라도 됨.

2. **손으로 만져보기** — 이미 팀에 `hermes doctor`가 통과된 환경이 있으니, unho님 `SETUP.md`대로 Slack에 연결해서 실제로 대화해보고 "며칠 뒤에도 이전 대화를 기억하는지" 체험. 개념보다 체감이 빠름.

3. **CLI 레퍼런스 훑기** — https://hermes-agent.nousresearch.com/docs/reference/cli-commands 에서 `memory`, `session` 관련 명령어만 골라서 실행해보며 저장소 구조(`~/.hermes/` 아래 뭐가 쌓이는지) 확인.

4. **소스코드는 memory 폴더만** — github.com/NousResearch/hermes-agent 클론해서 전체를 읽지 말고, 메모리 관련 모듈(예: FTS5 세션 검색, 요약 로직)만 골라 읽기. 이게 나중에 "팀 협업 지능 레이어"가 Hermes의 개인 기억과 어떻게 접합될지(Phase 4 ③) 설계할 때 필요한 부분.

5. **Mattermost 어댑터 감 잡기** — Slack 게이트웨이가 어떻게 붙는지 본 다음, "이 자리에 Mattermost REST/WebSocket을 붙이면 어떻게 될까"를 스스로 대입해보는 게 다음 실습(07/09 일정)의 핵심.

지금 팀 실습 폴더 구조(`shared/`에 배운 점 정리)를 그대로 활용해서, 각자 위 1~3단계 하고 막힌 점/배운 점을 `shared/`에 모으는 식으로 진행하면 좋을 것 같습니다.
