## 왜 자동으로 안 가져오게 막혀있나

`tools/mcp_tool.py`의 `_build_safe_env` 함수를 보면:

```python
def _build_safe_env(user_env):
    """Only passes through safe baseline variables (PATH, HOME, etc.) ...
    This prevents accidentally leaking secrets like API keys, tokens, or
    credentials to MCP server subprocesses.
    """
```

Hermes가 MCP 서버를 자식 프로세스로 띄울 때, **Hermes 자신의 환경변수를 통째로 물려주지 않고 PATH/HOME 같은 안전한 것만 남기고 나머지는 다 걸러냅니다.** `MATTERMOST_TOKEN`도 여기 걸려서 자동으로는 안 넘어갑니다. 의도적인 보안 설계입니다 — 안 그러면 아무 MCP 서버나 Hermes가 갖고 있는 모든 비밀 토큰을 다 볼 수 있게 되니까요.

## 대신 "같은 값을 두 번 안 쓰는" 방법은 있음

같은 파일에 `${VAR}` 문법으로 **환경변수 참조(치환)**를 지원합니다:

> Server config can contain ... `${VAR}` ... resolved against `os.environ` (which includes `~/.hermes/.env` loaded at startup)

즉 실제 토큰 값 자체는 `~/.hermes/.env` 파일 **한 곳에만** 적어두고, Hermes 자신의 Mattermost 어댑터 설정과 우리 MCP 서버의 `mcp_servers.env` 양쪽 다 그 값을 `${MATTERMOST_TOKEN}`처럼 **참조만** 하게 만들 수 있습니다.

```bash
# ~/.hermes/.env (한 곳에만 실제 값 저장)
MATTERMOST_TOKEN=실제_봇_토큰_값
MATTERMOST_URL=https://우리팀메신저.example.com
```

```yaml
# ~/.hermes/config.yaml
mcp_servers:
  mattermost_search:
    command: "python"
    args: ["/절대경로/mattermost_search_mcp.py"]
    env:
      MATTERMOST_TOKEN: "${MATTERMOST_TOKEN}"   # .env 값을 참조만, 값을 또 안 적음
      MATTERMOST_URL: "${MATTERMOST_URL}"
      MATTERMOST_TEAM_ID: "여기_팀_ID"
```

이렇게 하면 **"토큰이 바뀌면 `.env` 한 곳만 고치면 된다"**는 효율성은 챙기면서도, Hermes가 MCP 서브프로세스에 환경변수를 무분별하게 통째로 넘기지 않는 보안 설계는 그대로 유지됩니다. README에 이 방식으로 업데이트해드릴까요?
