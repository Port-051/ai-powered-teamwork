## A안: Hermes 내장 Slack 어댑터를 그대로 쓰기

```
Slack ──(Hermes가 이미 만들어둔 코드)── Hermes 전체(메모리+세션+도구)
```
- `hermes gateway setup`으로 토큰만 넣으면 끝, 코드 한 줄도 안 짜도 됨
- 멘션 감지, 스레드 처리, DM/채널별 세션 분리, 히스토리 백필까지 전부 이미 구현되어 있고 Hermes 팀이 유지보수함
- 단점: **Hermes가 정한 방식 그대로만** 동작함 — 지난번 말씀드린 대로 세션이 "대화방+멘션" 단위로 딱 격리되는 구조라서, 중간에 우리가 원하는 로직(예: "이 메시지, 팀 전체 지식으로 공유해야 하나?" 판단)을 끼워 넣을 자리가 없음

## B안: 내가 직접 Slack 봇을 만들고, 그 안에서 Hermes를 엔진으로 호출

```
Slack ──(내가 짠 slack_bolt 코드)── 내 코드 ──(Hermes를 API처럼 호출)── Hermes
```
- Hermes는 "API 서버" 모드로 켤 수 있어서(OpenAI 호환 HTTP 엔드포인트), 내가 만든 Slack 봇에서 Claude API를 직접 부르는 대신 **Hermes를 대신 부를 수** 있음
- 이러면 지난번 `bot.py`처럼 배관(멘션 감지, Slack 이벤트 처리)은 내가 직접 짜야 하지만, **그 배관 중간에 내 마음대로 로직을 끼워 넣을 수 있음**
- 예: "이 메시지 오면 Hermes한테 물어보기 전에, 먼저 우리 팀 공유 DB에서 관련 지식부터 찾아서 같이 넘겨주자" 같은 걸 할 수 있음

- (B) 우리가 직접 얇은 어댑터를 짜고, 그 안에서 Hermes를 엔진으로 호출 — 방금 말한 B안과 동일
