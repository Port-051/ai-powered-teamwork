**멀티프로파일 설정 B (멀티플렉싱)** 방법은 이렇습니다:

```bash
hermes config set gateway.multiplex_profiles true
hermes gateway restart
```

**동작 방식**: default profile 게이트웨이 프로세스 **하나**가 모든 profile의 어댑터(Mattermost 등)를 자기 안에서 같이 띄웁니다. 방법 A(profile마다 프로세스 따로 띄우기)와 달리 서버 자원(프로세스 개수)을 아끼는 대신, 한 프로세스에 다 몰려서 격리가 약해집니다.

**주의할 점 2가지**:
1. 멀티플렉싱을 켠 뒤에는 개별 profile에서 `hermes gateway start`를 직접 실행하면 안 됩니다 — 멀티플렉서가 이미 서빙 중이라 에러가 납니다.
2. 문서에는 "port-binding 플랫폼도 `/p/<profile>/` prefix로 접근 가능"이라고 적혀 있지만, 실제 코드(`api_server.py`)엔 profile 라우팅 코드가 없어서 이 부분은 실제로 안 됩니다(`webhook.py`만 해당). 다만 **Mattermost 어댑터는 WebSocket 방식이라 이 함정과 무관** — 멀티플렉싱 모드에서도 각 profile이 자기 Mattermost 어댑터를 정상적으로 띄울 수 있습니다. 단, profile마다 서로 다른 Mattermost 봇 토큰은 여전히 필요합니다(토큰 겹치면 시작 시 충돌 에러).
