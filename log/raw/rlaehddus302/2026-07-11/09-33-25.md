`use-mcp-with-hermes.md` 공식 가이드에도 정확히 우리 상황이 예시로 나와 있습니다 — "connect Hermes to internal APIs, databases, or company systems **without modifying Hermes core**". 실제로 하는 순서는 이렇습니다.

## 1단계 — Mattermost 쪽 준비 (봇 토큰)
- Mattermost 시스템 콘솔에서 봇 계정 만들고 **Personal Access Token** 발급
- 검색하려는 채널에 그 봇을 멤버로 넣기 (Mattermost의 `/posts/search` API는 봇이 속한 채널만 검색됨 — private 채널까지 보려면 그 채널에도 초대해야 함)

## 2단계 — MCP 서버 코드 작성 (우리가 새로 짜는 유일한 부분)
Python `mcp` SDK(`FastMCP`)로 "도구 하나"를 노출하는 아주 작은 서버를 짭니다. 대략 이런 모양입니다:

```python
# mattermost_search_mcp.py
import os, requests
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("mattermost-search")
MM_URL = os.environ["MATTERMOST_URL"]
MM_TOKEN = os.environ["MATTERMOST_BOT_TOKEN"]

@mcp.tool()
def search_mattermost(query: str, team_id: str) -> list[dict]:
    """Mattermost 팀 메시지에서 query로 검색한다."""
    resp = requests.post(
        f"{MM_URL}/api/v4/teams/{team_id}/posts/search",
        headers={"Authorization": f"Bearer {MM_TOKEN}"},
        json={"terms": query, "is_or_search": False},
        timeout=10,
    )
    resp.raise_for_status()
    return resp.json()

if __name__ == "__main__":
    mcp.run()  # stdio transport
```

이게 전에 얘기한 "별도 프로세스" 그 자체입니다 — Hermes도 Mattermost도 소스를 안 건드리고, 이 파일 하나가 독립 프로세스로 떠서 Mattermost REST API만 호출합니다.

## 3단계 — Hermes 쪽에 등록
`~/.hermes/config.yaml`에 추가:

```yaml
mcp_servers:
  mattermost_search:
    command: "python"
    args: ["/path/to/mattermost_search_mcp.py"]
    env:
      MATTERMOST_URL: "https://우리팀메신저.example.com"
      MATTERMOST_BOT_TOKEN: "여기_봇_토큰"
    tools:
      include: [search_mattermost]   # 노출 범위 딱 이 도구 하나로 제한 (가이드 권장사항)
```

## 4단계 — 확인
```
hermes chat
```
켠 다음 `/reload-mcp` 하고, "지금 쓸 수 있는 MCP 도구 뭐 있어?"라고 물어보면 `search_mattermost`가 잡히는지 확인. 그다음 실제로 "지난주에 배포 관련해서 뭐라고 했었는지 찾아봐" 같은 질문을 던져서 봇이 그 도구를 스스로 호출하는지 테스트합니다.
