좋은 질문인데, 오해가 있습니다 — **`${...}`는 Python 코드에 들어가는 게 아닙니다.** 이 부분은 그대로 두는 게 맞습니다.

```python
MATTERMOST_URL = os.environ.get("MATTERMOST_URL", "").rstrip("/")
MATTERMOST_BOT_TOKEN = os.environ.get("MATTERMOST_TOKEN", "")
```

## `${VAR}`가 처리되는 위치는 딱 한 곳 — `config.yaml`

치환(substitution)은 **Hermes가 config.yaml을 읽는 시점**에 이미 다 끝납니다. 순서를 다시 보면:

1. **`~/.hermes/config.yaml`**에 이렇게 적혀 있습니다:
   ```yaml
   env:
     MATTERMOST_TOKEN: "${MATTERMOST_TOKEN}"
   ```
2. Hermes가 이 config를 읽으면서, `.env` 파일을 먼저 로드하고 → `${MATTERMOST_TOKEN}`이라는 **문자열**을 발견하면 → 그걸 `.env`에 있는 **진짜 토큰 값**(예: `xoxb-abc123...`)으로 바꿔치기합니다. (`_interpolate_env_vars` 함수가 하는 일)
3. 이 치환이 끝난 **진짜 값**을 가지고 Hermes가 우리 파이썬 스크립트를 자식 프로세스로 실행하면서, 그 프로세스의 환경변수로 `MATTERMOST_TOKEN=xoxb-abc123...`를 심어줍니다.

즉 **우리 `mattermost_search_mcp.py`가 실행되는 시점에는 `${...}`라는 글자는 이미 세상에서 사라지고 없습니다.** `os.environ.get("MATTERMOST_TOKEN", "")`이 호출되는 시점에 `os.environ`에는 이미 실제 토큰 값이 들어있는 평범한 문자열 하나뿐입니다.

## 비유하면

- `${MATTERMOST_TOKEN}`은 **주문서에 적는 "메뉴 이름"** 입니다 — `config.yaml`(주문서)에만 쓰는 표기법
- 우리 파이썬 코드는 **완성된 음식을 받아먹는 사람** — "메뉴 이름"이 뭐였는지는 몰라도 되고, 그냥 `os.environ.get(...)`으로 접시(환경변수)에 이미 담겨온 값을 꺼내 쓰기만 하면 됨

그래서 **파이썬 코드는 원래 그대로가 정답**이고, 실제로 바뀐 건 어제 말씀드린 대로 딱 하나 — 읽는 키 이름을 `MATTERMOST_BOT_TOKEN` → `MATTERMOST_TOKEN`으로 바꾼 것뿐입니다. `${}` 치환 로직 자체는 우리가 짤 필요도 없고, Hermes가 알아서 다 해줍니다.
