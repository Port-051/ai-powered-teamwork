## 2. 프로젝트 기획서 (10p 이내)

## □ 목적 및 필요성

### ㅇ 문제인식
- 비개발자 팀은 AI(ChatGPT·Claude 등)를 **개인이 각자 브라우저에서** 산발적으로 쓴다 → 대화·결정·노하우가 흩어져 **팀 자산으로 축적되지 않는다.**
- 팀원이 휴가·퇴사하면 그가 알던 맥락이 통째로 사라진다("그 건 어떻게 됐지?"를 사람 붙잡고 물어야 함).
- 기존의 지식관리·협업 도구(git 기반 등)는 **비개발자에게 진입장벽이 높다**(터미널·클론·커밋).
- 슬랙 등 상용 메신저+AI는 **데이터가 외부 회사 서버를 경유** → 업무 기밀 부담.
- `[확인필요: 실제 인터뷰/설문 수치]` — T-GATES처럼 "타겟 N곳 인터뷰 → M곳이 문제 언급" 형태의 1차 검증 데이터 필요.

### ㅇ 기획의도
- 팀이 **평소 쓰던 메신저에서 AI에게 말 걸듯** 일하면, 기록·공유·개인화가 **자동으로** 일어나게 한다.
- 검증된 오픈소스(Hermes 학습엔진 + Mattermost 메신저)를 조합하되, **아무도 안 만든 '팀 협업 지능 레이어'를 우리가 창조**한다.

## □ 프로젝트 개요

### ㅇ 프로젝트 소개
- 팀이 자기 서버에 **Mattermost(오픈소스 메신저)를 설치** → 모든 데이터가 우리 서버에만 남음(데이터 주권).
- 팀원이 채널/DM에서 **`@ai` 멘션** → AI 응답. 모든 대화·결정이 자동 기억되어 **팀 공유 뇌 + 개인 학습 에이전트**로 축적.

### ㅇ 주요 기능
| 기능 | 설명 |
|---|---|
| 주요 기능1 — 메신저 내 AI 호출 | Mattermost에서 `@ai` 멘션으로 AI와 대화(비개발자 무설정 사용) |
| 주요 기능2 — 팀 공유 지능 | "여운호가 알아낸 걸 김동연도 자기 AI에게 물으면 안다" (권한·비밀 보호) |
| 주요 기능3 — 개인 학습 에이전트 | 팀원 각자를 학습해 개인 최적화(Hermes 학습 루프·사용자 모델링 활용) |

### ㅇ 시장분석
- 경쟁/유사: Slack AI, MS Copilot(상용·외부서버·구독), Notion AI 등. **차별점 = 자체호스팅(데이터주권) + 개인·팀 이중 지능 + 비개발자 무설정.**
- `[확인필요: 시장 규모 수치, 경쟁제품 비교표]`

### ㅇ 시스템 구성도
```
[팀원] ─@ai멘션→ [Mattermost 순정·자체호스팅]

              [★우리 코드: Mattermost어댑터 + 팀협업지능레이어 + 개인↔팀 접합]
                      │
              [Hermes 포크(MIT): 개인학습·기억·사용자모델링]
```
