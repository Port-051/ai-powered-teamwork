# teambrain-process

TeamBrain 레포(`log/raw/`) 아래 쌓인, 팀원 3명(여운호·김동연·신홍재)과 멘토 김선만의 프롬프트 입출력 원본을 정리하는 작업이다. 누가 이 스킬을 실행하든, `log/raw/` 아래 실제로 존재하는 모든 폴더 이름 기준으로 처리 안 된 기록을 대상으로 한다.

## 절차

1. **대상 찾기**: `log/raw/<user>/<YYYY-MM-DD>/` 형태의 폴더를 전부 찾는다. 오늘 날짜 폴더는 아직 그날 진행 중일 수 있으니 기본적으로 **오늘보다 이전 날짜**만 처리 대상으로 삼는다 (사용자가 명시적으로 "오늘 것도 처리해줘"라고 하면 포함).

2. **사람별 · 날짜별 요약 생성**: 각 `<user>/<date>/` 폴더 안의 `*.md` 파일(턴 하나당 하나)을 시간순으로 전부 읽고, 다음을 뽑아 `log/processed/<user>/<date>.md`에 정리해서 쓴다.
   - 그날 무엇을 했는지 (작업/조사/논의 요약, 시간순이 아니라 주제별로 묶어도 됨)
   - 결정된 것 / 남은 질문
   - 잡담이나 반복된 확인 요청처럼 가치 없는 내용은 걸러낸다 — raw처럼 전부 옮겨적지 않는다.

3. **팀 전체가 알아야 할 내용은 `port_051/`로 추출**: 개인 작업 로그가 아니라 팀 전체 의사결정, 아키텍처 변경, 일정 변경, 리스크/이슈처럼 **다른 팀원도 반드시 알아야 하는 내용**만 골라 `port_051/` 아래에 주제에 맞는 파일로 정리한다.
   - `port_051/` 폴더나 적당한 주제 파일이 없으면 새로 만든다 (예: `port_051/decisions.md`, `port_051/architecture.md`, `port_051/schedule-changes.md` 등 — 이미 있는 파일이 있으면 그걸 이어서 쓰고, 애매하면 사용자에게 물어봐도 된다).
   - 같은 내용을 중복해서 여러 파일에 쓰지 않는다. 이미 있는 내용이면 갱신만 한다.

4. **원본 raw 이동**: 2번에서 처리에 사용한 `log/raw/<user>/<date>/` 폴더 전체를 그대로 `log/archive/<user>/<date>/`로 옮긴다 (`git mv`). 그래서 `log/raw/` 아래 날짜 폴더가 남아있다는 것 자체가 "아직 처리 안 됨"이라는 표시가 유지된다.

5. **커밋/푸시**: 이 스킬로 만들어진 변경(`log/processed/`, `log/archive/`, `port_051/`)은 `log/raw/` 자동 push 대상이 아니다 — CLAUDE.md의 일반 규칙대로, 무엇을 바꿨는지 팀원에게 짧게 보여주고 확인받은 뒤에만 커밋·푸시한다.

## 주의

- raw 원본 내용 자체를 함부로 삭제하지 않는다 — 반드시 archive로 이동만 한다.
- 여러 팀원의 로그를 동시에 처리해도 날짜 폴더 단위로 옮기기 때문에 서로 충돌하지 않는다.
- 처리 대상 파일이 하나도 없으면 ("처리할 새 로그가 없습니다") 짧게 보고하고 끝낸다.
