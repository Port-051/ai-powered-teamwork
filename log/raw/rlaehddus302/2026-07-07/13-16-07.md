## App Token vs Bot Token — "용도"가 완전히 달라요

| | App Token (`xapp-`) | Bot Token (`xoxb-`) |
|---|---|---|
| 누구를 대표하나 | **앱 자체** (사람도 봇도 아닌, 그냥 이 프로그램) | **봇이라는 가상의 사용자 계정** |
| 뭘 할 때 쓰나 | **슬랙에 연결(전화)을 걸 때만** | **실제로 뭔가 행동(메시지 보내기 등)할 때** |
| 비유 | 건물에 들어갈 수 있는 "출입증" (일단 안으로 들어가기만 함) | 건물 안에서 "이 부서 업무를 처리할 수 있는 직원증" (실제 업무 수행) |

즉:
- **App Token** = 아까 설명한 "전화 걸어서 통화선 여는 것"에만 쓰여요. 이걸로는 메시지를 못 보내요.
- **Bot Token** = 그 통화선으로 "누가 멘션했다"는 소식을 받은 다음, **실제로 답장을 보낼 때** 쓰는 열쇠예요 (`chat:write` 권한이 여기 달려있죠).

둘 다 있어야 완전한 왕복(멘션 받기 + 답장 보내기)이 돼요.

## Bot Token Scopes vs User Token Scopes — "누구 이름으로" 행동하나의 차이

이건 3단계 화면에서 **"이 앱이 행동할 때, 누구 자격으로 행동하는가"**를 정하는 거예요.

### Bot Token Scopes
- **봇이라는 별도의 가짜 계정** 자격으로 행동해요.
- 예를 들어 `chat:write`를 Bot Token Scope에 넣으면, 메시지를 보낼 때 **"ai-bot-test APP"**이라는 이름으로 채널에 올라가요 (실제 사람이 아니라 봇이 보낸 걸로 표시됨).
- 우리가 지금 만드는 것 = 이거예요. **봇이 스스로 답장하는 것**이니까요.

### User Token Scopes
- **앱을 설치한 실제 사람(예: 김동연)의 계정 자격**으로 행동해요.
- 예를 들어 `chat:write`를 User Token Scope에 넣으면, 메시지가 **"김동연"** 이름으로 올라가요 — 마치 김동연님이 직접 친 것처럼요.
- 이건 "이 사람을 대신해서 뭔가 하는" 용도예요. 예를 들어 "이 사람이 볼 수 있는 채널만 검색해서 알려줘" 같은 기능을 만들 때 쓰여요 — **지난번에 얘기했던 "Mattermost 검색을 그 사람 본인 토큰으로 호출하면 권한이 자동으로 걸러진다"는 얘기랑 같은 원리**예요. 그 사람 권한 그대로 상속받는 거죠.

## 정리 — 우리 연습용 봇에선

**Bot Token Scope만 쓰면 돼요** (`app_mentions:read`, `chat:write`). User Token Scope는 안 건드려도 됩니다 — 왜냐면 우리가 만드는 건 "봇이 스스로 답하는 것"이지, "특정 사람인 척 행동하는 것"이 아니니까요. 나중에 진짜 프로젝트에서 "이 사람 권한만큼만 팀 지식 검색해서 답해주기" 같은 기능을 만들 때가 되면, 그때 User Token 개념이 다시 나올 거예요.
