저 코드 안에 있는 get은 그냥 기본 지원되는 함수인가?

### assistant


아니요, 그건 제가 이 파일 안에서 직접 만든 함수입니다. Python이나 MCP SDK가 기본으로 제공하는 게 아닙니다.

```python
def _get(path: str, params: dict | None = None) -> dict:
    resp = requests.get(
        f"{MATTERMOST_URL}/api/v4/{path.lstrip('/')}",
        headers=_headers(),
        params=params or {},
        timeout=10,
    )
    resp.raise_for_status()
    return resp.json()
```

**실제로 HTTP GET 요청을 보내는 건 `requests.get()`** — 이건 `requests` 라이브러리(`requirements.txt`에 넣은 그 패키지)가 제공하는 진짜 함수입니다.

**`_get`은 그걸 감싼 우리 코드**입니다. 매번 도구 함수마다 이 4줄(URL 조립, 인증 헤더, 에러 체크, JSON 파싱)을 반복해서 쓰기 귀찮으니까, 공통 부분을 한 군데로 묶어놓은 겁니다. `_post`도 마찬가지로 `requests.post()`를 감싼 우리 헬퍼고요.

**이름 앞의 언더스코어(`_get`, `_post`, `_headers`, `_resolve_team_id`, `_flatten_post`)**는 Python 관례로 "이건 이 파일 내부에서만 쓰는 보조 함수다, 외부에서 직접 부르지 마라"는 표시입니다. 실제로 `@mcp.tool()` 데코레이터가 안 붙어 있어서 **MCP 도구로도 노출되지 않습니다** — Hermes(LLM) 눈에는 안 보이고, `search_mattermost` 같은 실제 도구 함수들이 내부적으로만 호출하는 배관(plumbing) 역할입니다.

정리하면: `requests.get`(라이브러리 제공) → `_get`(우리가 감싼 것) → `search_mattermost` 등 6개 도구(LLM에게 노출되는 것), 이렇게 3단 구조입니다.
