## 1. Hermes 메모리가 "1인용"이라는 게 무슨 뜻인가

찾아보니 Hermes(Nous Research, MIT)의 기억 구조는 이렇게 생겼어요. 전부 **"한 명(=나)"을 중심으로** 설계돼 있습니다:

| 층 | 하는 일 | "1인용"이라는 뜻 |
|---|---|---|
| **Persistent facts** (영속 사실) | 나에 대한 고정 사실을 append-only(계속 덧붙이기만 하는) 로그에 쌓아 프롬프트에 항상 넣어줌 | 전부 *내* 사실. 누가 알아도 되는지 개념이 없음 |
| **SessionDB** (과거 대화) | 지난 세션 전체를 전문검색(FTS5)으로 저장 → "검색 후 요약"으로 회상 | *내* 세션만 검색 대상 |
| **Skills** (익힌 작업법) | 경험에서 스킬을 스스로 만들고(skill_manage로 생성·수정·폐기) 재사용 | *내가* 익힌 것, *나만* 씀 |
| **User modeling** (Honcho) | "너는 누구인가"를 dialectic 방식으로 계속 정교화. user peer + agent peer 2개 표현 유지 | 화자 1명 + AI 1명, 딱 두 관계 |

즉 Hermes는 **"나(1명) ↔ AI(1명)"** 관계를 깊게 파는 데 최적화돼 있어요. 그런데 여러분 제품은 **"팀(N명) ↔ AI"** 예요. 그래서 그대로 쓰면 "김동연의 AI", "여운호의 AI"가 각각 따로 놀 뿐, *팀이 뭘 아는지*는 아무도 모르는 상태가 됩니다 — 이게 기획서 문제인식의 "AI는 개인용, 팀은 깜깜이"와 정확히 같은 문제예요.

**멘토님 말씀 = "그 검증된 1인용 구조를 처음부터 다시 만들지 말고, 각 층을 팀 단위로 확장(집계·공유·권한)하는 레이어만 얹어라."** 이게 여러분 아키텍처의 ②번 박스 그 자체입니다.

## 2. 그래서 "팀용으로 변환"이 구체적으로 무슨 작업인가

각 메모리 층마다 "1인용 → 팀용"이 이렇게 대응됩니다:

**① Persistent facts → 소유자·가시성 태그를 붙인 공유 사실**
- 사실 하나하나에 `누구 것인지 / 개인용인지 팀 공유인지` 딱지를 붙입니다.
- **개인 뇌** = 내 개인 사실 + 팀 공유 사실. **팀 공유 뇌** = 모든 팀원의 "팀 공유" 사실을 합친 것.
- 여기서 **개인 사실이 팀 공유로 올라갈 때 통과하는 "권한·비밀 필터"**가 새로 짜야 하는 핵심(=기획서 ③ 개인↔팀 브릿지)이에요. "여운호가 알아낸 걸 김동연도 안다"가 이 합집합 조회로 실현됩니다.

**② SessionDB → 채널 권한에 맞춘 검색 범위**
- 세션(대화 묶음)마다 `어느 채널 / 누가 참여 / 공개 범위` 메타데이터를 답니다.
- 검색할 때 "이 사람이 접근 가능한 세션"으로만 범위를 좁혀요. 이건 Mattermost 채널 권한과 1:1로 매핑하면 자연스럽게 됩니다 (비공개 채널 대화가 아무한테나 검색되면 안 되니까).

**③ Skills → 팀 자산으로 승격되는 스킬**
- 한 명이 만든 "주간보고서 뽑는 법" 스킬을 개인 것으로 둘지, 팀 전체가 재사용하게 승격할지 구분합니다. 팀 지능이 *노하우 수준*에서도 쌓이는 부분.

**④ User modeling → 팀 정체성 표현 추가**
- 여기가 운이 좋은 지점인데, **Honcho는 이미 "peer(참여자)"가 기본 단위**예요. user와 AI를 각각 peer로 두고, 한 workspace 안에 여러 peer를 담습니다. 즉 **멀티유저 발판이 엔진에 이미 있어요.**
- 그래서 매핑이 깔끔합니다:

  ```
  Mattermost 팀        → Honcho workspace (하나의 팀 기억 공간)
  Mattermost 사용자    → Honcho peer      (팀원 각자 = 개인 에이전트)
  Mattermost 채널/스레드 → Honcho session   (대화 묶음)
  ```
- 여기에 **"팀 전체를 하나로 보는 집합 표현(팀 peer)"**을 하나 더 얹는 게 우리 오리지널 부분입니다.

## 3. 정리 — 우리가 실제로 새로 짜는 코드

멘토님 방향대로면 "엔진 재발명 0, 우리는 변환·연결 레이어만"이 되고, 이게 **딱 기획서 ②③번**이자 소마 어필 포인트("개인 AI들을 팀 협업 지능으로 엮었다")예요. 구체 작업 4개:

1. **매핑 어댑터** — Mattermost의 사용자/채널/스레드를 Honcho의 peer/workspace/session에 연결
2. **팀 집계 뷰** — 개인별 메모리(사실·세션·스킬) 위에 "팀 공유 합집합" 조회를 얹기
3. **권한·비밀 브릿지** — 개인 → 팀 공유로 올라갈 때 거르는 필터 (제일 novel, 제일 어려움)
4. **(선택) 팀 정체성 표현** — 팀 전체를 하나의 학습 대상으로 모델링
