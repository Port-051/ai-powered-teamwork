# TeamBrain 학습·구축 로드맵 (Port_051)

> 대상: 팀원 전원(비개발 배경 포함). **아무것도 모른다는 전제**로, 진짜 기초 → 부품 3개 → 우리가 만들 "붙이는 레이어"까지.
> 원칙: **읽기 20% : 직접 돌려보기 80%.** 코드는 Claude Code로 만들되, "설계·이해·검수"는 사람 몫.
> 각 항목은 완료 기준(체크박스)을 통과하고 다음으로.

---

## 전체 지도

```
Phase 0  진짜 기초 (이미 있으면 스킵)         터미널·HTTP·언어 읽기
   ↓
Phase 1  공용 개념 (전원 공통)                팀 대화의 공용어
   ↓
Phase 2  부품 3개 손에 익히기                 Mattermost / Hermes / Honcho
   ↓
Phase 3  ★붙이는 레이어 (우리가 만드는 것)★   어댑터 + 팀집계 + 권한  = 실력·취업 핵심
   ↓
Phase 4  운영·배포                            Docker Compose / AWS / 시크릿
```

---

## Phase 0 — 진짜 기초 (2~3일, 이미 되면 스킵)

- [ ] 터미널: `cd`/`ls`로 폴더 오가며 파일 열기
- [ ] Git 개념: 커밋(저장 시점 기록)·푸시(공용 저장소에 올리기)가 뭔지 *알아듣기* (실행은 Claude가 대신)
- [ ] Python **읽기**: 함수·변수·if·반복문·import 보고 대충 뭐 하는지 말하기
- [ ] HTTP 기본: 요청/응답, URL, 상태코드(200 성공 / 404 없음) 감 잡기

학습법: 이 폴더에서 Claude Code한테 "이거 초등학생도 알게 설명해줘"로 그때그때.

---

## Phase 1 — 공용 개념 (2~3일, 전원 공통)

역할 불문 다 아는 공용어. 깊게 말고 감만.

- [ ] **LLM / 토큰 / 컨텍스트 윈도우** — AI가 한 번에 읽는 글엔 한계가 있다 → 왜 요약·검색하는지
- [ ] **에이전트 & 툴 콜** — AI가 대화만 아니라 도구를 직접 호출해 일한다 → "파일 생성·수정"의 원리
- [ ] **REST API** — 요청-응답식 프로그램 대화
- [ ] **WebSocket** — 계속 연결해 실시간 수신 (멘션 즉시 받기)
- [ ] **JSON** — 프로그램끼리 쓰는 데이터 표기법
- [ ] **봇 계정 / 웹훅** — AI용 메신저 계정 / 이벤트 알림 콜백
- [ ] **프로세스 분리** ★ — 우리 코드는 Mattermost 밖 별도 프로그램 (AGPL 라이선스 필수, PLAN 6-1)
- [ ] **Docker / 컨테이너** — 프로그램을 설정째 담은 실행 상자

완료 기준: 팀 회의에서 위 단어가 나올 때 아무도 못 알아듣는 사람이 없다.

---

## Phase 2 — 부품 3개 손에 익히기 (3~5일, 이번 주 핵심)

전원이 셋 다 "실행"까지 한 번씩 → 그다음 담당 부품 깊게.

### 부품 A. Mattermost — 담당 김동연 (인프라)
> 우리가 만들 게 아니라 설치해서 쓰는 메신저

- [ ] A-1 Docker로 내 PC에 Mattermost 띄우기
- [ ] A-2 팀·채널 만들고 카톡처럼 써보기
- [ ] A-3 봇 계정 만들고, 봇 토큰으로 REST API 호출해 **채널에 메시지 보내기** 성공
- [ ] A-4 WebSocket 연결해 **누가 메시지 쓰면 내 프로그램이 수신** 성공

완료 기준: 내 프로그램이 메시지를 받고+보낼 수 있다 (멘션 왕복 뼈대 완성).

### 부품 B. Hermes Agent — 담당 여운호 (AI 엔진)
> 포크해서 심장으로 쓰는 개인 AI

- [ ] B-1 hermes-agent 클론해 로컬 실행, AI와 대화
- [ ] B-2 **메모리 실물 확인** — 3층(영속 사실 로그 / SessionDB / 스킬)이 어느 파일/DB에 어떤 모양인지 열어보기
- [ ] B-3 skill_manage로 AI가 스킬 만들고 고치는 것 관찰

완료 기준: "이 AI의 기억이 물리적으로 어디에 어떤 모양으로 저장되나"를 팀에 그림으로 설명. (7/09 메모리 구조 학습)

### 부품 C. Honcho — 담당 여운호+신홍재 (팀 지능의 뿌리)
> Hermes의 기억·사용자모델링 하부 저장소. 팀 전환의 발판.

- [ ] C-1 문서에서 **workspace / peer / session** 데이터 모델 파악
- [ ] C-2 ★**1순위**: "한 session에 여러 peer 되나? peer별 기억 격리되나?" 스키마 직접 검증

완료 기준: `팀=workspace, 팀원=peer, 채널=session` 매핑이 되는지 답이 나온다. **(Phase 3 난이도를 좌우 — 제일 중요)**

---

## Phase 3 — ★붙이는 레이어★ (2~4주, 우리가 만드는 것)

진짜 실력·오리지널·백엔드 취업 핵심. Phase 2 통과 후 시작. 1→5 순서, 각 단계 "제일 작은 것부터 실제 동작".

### 3-1. API 통합 실전  — (백엔드: REST/WebSocket 클라이언트, 외부 연동)
- 최소 목표: `@ai 안녕` → 우리 코드 수신 → Hermes에 전달 → 답을 채널에 되돌리기
- [ ] 완료 기준: 멘션 한 줄이 사람 개입 없이 답으로 돌아온다 (= 7/16 MVP 심장)

### 3-2. 어댑터 설계  — (백엔드: 어댑터 패턴, 계층 분리)
- 최소 목표: Mattermost 사용자·채널·스레드 → Honcho peer·workspace·session 매핑 함수
- [ ] 완료 기준: Mattermost가 바뀌어도 엔진 코드는 안 건드리게 "번역기"가 분리돼 있다

### 3-3. 데이터·상태 모델링  — (백엔드: 데이터 모델링, 집계 쿼리)
- 최소 목표: 사실에 `owner`, `visibility(개인/팀공유)` 필드 + "이 사람이 볼 수 있는 것만" 조회
- [ ] 완료 기준: 같은 질문을 두 사람이 물으면 각자 권한에 맞게 (다르거나 공유된) 답이 나온다

### 3-4. 권한·인가 설계 ★  — (백엔드: Authorization/접근제어 — 모든 백엔드의 심장)
- 최소 목표: 규칙 하나부터 — "비공개 채널 대화는 팀 검색에 안 뜬다"
- [ ] 완료 기준: "여운호의 비밀 메모가 김동연 검색에 안 샌다"가 실제로 막힌다
- 제일 어렵고 제일 novel. **이력서 스토리의 핵심.**

### 3-5. 시스템 설계  — (백엔드: 서비스 간 통신, 동시성, 운영)
- 최소 목표: 우리 레이어가 별도 프로세스로 돌고, 두 명 동시 멘션에도 안 꼬임
- [ ] 완료 기준: 동시 사용에도 답이 안 섞이고, 문제 시 로그로 추적된다

**Phase 3 전체 완료 기준**: 한 명이 알아낸 걸 다른 팀원이 (권한 내에서) 자기 AI로 물으면 안다 = 기획서 주요기능 2번 실현.

## "코드 짤 일 거의 없나?" — 정반대

- **안 짜는 것(재발명 안 함)**: Mattermost · Hermes · Honcho (가져다 씀 = 전체 줄 수의 ~90%)
- **짜는 것(우리 원본)**: Phase 3 전체(어댑터·모델링·권한·시스템) + Phase 4 배포 + 대시보드 = ~10%지만 **제일 어렵고 가치 있는 부분**
- Claude Code로 만들어도 **설계·이해·검수·디버깅은 사람 몫** → "적게 짜되, 짜는 것마다 어려운 원본 코드"
