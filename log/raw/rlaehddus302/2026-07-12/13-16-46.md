우리 회의 방향(한국어 + "누가 말했는지" 구분 필요)에 맞춰 실용적인 후보만 추렸어요.

## 회의 전사에 실제로 쓸 만한 것

| 라이브러리 | 특징 | 우리 용도 적합성 |
|---|---|---|
| **faster-whisper** | Whisper를 CTranslate2로 다시 짜서 **최대 4배 빠르고 메모리 적게** 씀. 사실상 self-host 표준. | ⭐ 기본으로 이걸 씀. 한국어 지원(99개 언어). |
| **WhisperX** | faster-whisper에 **화자 분리(diarization, "누가 말했는지" 구분)** + 단어 단위 타임스탬프 추가. | ⭐⭐ **회의 전사엔 이게 정답.** 회의는 여러 사람이 말하니까 "누가 무슨 말 했는지"가 핵심. |
| whisper.cpp | C++ 구현, GPU 없이 CPU만으로도 돌아감. | GPU 없는 고객 서버 대비용 백업 옵션. |

이 셋 다 **MIT 계열 라이선스라 우리 프로젝트에 붙여도 라이선스 문제 없습니다.** (CLAUDE.md의 카피레프트 확인 원칙만 지키면 됨.)

## "무료"의 진짜 의미 — 비용은 GPU로 옮겨감

라이브러리 자체는 공짜지만, **모델을 돌릴 컴퓨팅(GPU)은 필요**합니다. 여기가 중요해요:

- 가장 정확한 `large-v3` 모델은 **VRAM 10GB 이상** 필요.
- 님 노트북의 **RTX 4050은 6GB**라서 large-v3는 빡빡하고, `medium` 모델이나 양자화(quantized)된 large를 faster-whisper로 돌리는 게 현실적입니다. 회의록 품질엔 medium도 충분히 쓸 만해요.
- 실제 배포(고객사)에서는 고객 서버 GPU에서 돌리거나, GPU 없으면 whisper.cpp로 CPU 처리(느리지만 됨).

## 그래서 우리 파이프라인은 이렇게 그려집니다

```
Mattermost Calls (음성 통화·녹음, 무료)
     │  녹음된 오디오 파일을 API로 받음
우리 레이어 (별도 프로세스)
     │  → WhisperX로 전사 + 화자분리   ← 여기가 무료 STT
     │  → 전사 텍스트를 Hermes/우리 팀지능 레이어로
결과: "누가 무슨 결정을 했는지" 텍스트로 남고 업무로 연결
```

이러면 **Mattermost 유료(Enterprise) 라이선스 없이도** 회의 전사가 됩니다 — 지난번 말한 "방법 B"가 이렇게 성립해요. 고객에게 유료 플랜 강요 안 해도 되니 우리 오픈코어 모델과 잘 맞습니다.

한 가지 확인이 필요한 건, WhisperX의 화자분리 부분이 내부적으로 `pyannote`라는 모델을 쓰는데 **이건 사용 전 무료 동의 절차가 있고 라이선스 조건을 따로 봐야** 합니다. 이 방향으로 확정되면 그때 pyannote 라이선스가 우리 상업적 사용(매니지드 구독)에 걸리는 게 없는지 제가 정확히 확인해드릴게요.
