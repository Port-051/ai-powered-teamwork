## 1. 설치하면 실제로 뭐가 벌어지나

설치는 한 줄:
```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```
이 스크립트가 알아서 Python, Node.js, ripgrep, ffmpeg 같은 의존성을 깔고, 레포를 클론하고, 가상환경(venv)을 만들고, 전역에서 쓸 수 있는 `hermes` 명령어를 등록합니다. 사람이 할 일은 그 다음 LLM(대화 엔진)을 뭘 쓸지 고르는 것뿐입니다.

`hermes setup`을 실행하면 3가지 모드 중 고름:
- **Quick Setup(Nous Portal)** — 무료 OAuth 로그인만으로 바로 씀. API 키 필요 없음. Nous Research가 자체 제공하는 모델 게이트웨이.
- 그 외 OpenRouter, OpenAI, 커스텀 엔드포인트 등 직접 API 키를 넣는 방식도 가능.

설치가 끝나면 두 갈래 길이 있습니다:
- **최소 구성으로 바로 끝내기** — 도구·스킬·플러그인·메신저 연동은 다 꺼진 채로, 그냥 "대화만 되는 에이전트"로 시작
- **전체 설정 마법사 따라가기** — 도구, 스킬, 플러그인, MCP, 메신저 연동까지 하나씩 켜면서 세팅

## 2. 처음 실행했을 때 (Quickstart)

```bash
hermes          # 클래식 CLI
hermes --tui    # 요즘 권장하는 터미널 UI 버전
```
실행하면 지금 쓰는 모델, 사용 가능한 도구 목록, 스킬 목록이 적힌 환영 배너가 뜨고 바로 대화창이 열립니다. 여기서부터는 그냥 채팅하듯 말 걸면 됩니다 — 이게 챗봇과 똑같아 보이는 지점이지만, 뒤에서 대화 내용이 자동으로 memory 파일에 쌓인다는 게 다른 점입니다(이전 답변에서 설명한 MEMORY.md/USER.md).

## 3. "게이트웨이(gateway)"라는 개념 제대로 이해하기

이게 사실 Hermes 아키텍처에서 가장 중요한 개념입니다. **게이트웨이 = 백그라운드에서 계속 돌아가는 프로세스 하나가, 내가 설정해둔 모든 메신저 플랫폼에 동시에 연결되어 있는 구조**입니다.

- Telegram, Discord, Slack, WhatsApp, Signal, Mattermost 등 20개 이상 플랫폼을 **각각 별도 봇 프로세스로 띄우는 게 아니라, 게이트웨이 프로세스 하나가 전부 물고 있음.**
- 각 플랫폼 어댑터는 "메시지를 받아서 → 대화방(chat)별 세션 저장소에 넣고 → AIAgent(실제 두뇌)로 넘겨서 처리 → 응답을 다시 그 플랫폼으로 돌려줌"이라는 동일한 파이프라인을 탑니다.
- **세션은 대화방 단위로 유지**됩니다. 예를 들어 Telegram에서 얘기하다가 Discord로 옮겨도 (같은 대화방으로 매핑돼 있다면) 문맥이 안 끊깁니다. 반대로 서로 다른 채널/DM은 기본적으로 독립된 세션(=독립된 기억 문맥)입니다.
- **세션 리셋 정책**: 매일 정해진 시각에 리셋하거나, 일정 시간(기본 1440분=24시간) 동안 아무 말 없으면 자동 리셋되도록 설정 가능.

### 플랫폼 공통 패턴
- **스레드**: Telegram, Discord, Slack, Google Chat 등에서 대화를 갈래로 나눠 이어갈 수 있음
- **반응(이모지 리액션)**: Discord, Slack, Matrix 등에서 피드백 수단으로 지원
- **타이핑 표시**: "지금 생각 중"임을 보여줌 (플랫폼별로 켜고 끌 수 있음)
- **음성**: 텍스트를 음성으로 읽어주는 기능이 Telegram, Discord, Slack 등에서 지원됨

### 명령어는 플랫폼 상관없이 동일
`/new`(새 대화 시작), `/model`(AI 모델 변경), `/status`(세션 상태 확인) 같은 슬래시 명령어가 어느 플랫폼에서든 똑같이 작동합니다. 일반 잡담은 관리자 권한 여부와 상관없이 누구나 가능하고, 특정 명령어만 권한을 나눠서 제한할 수 있습니다.

### 접근 제어
- **허용목록(allowlist)**: 환경변수로 "이 사람들만 봇에 말 걸 수 있음" 지정 (예: `TELEGRAM_ALLOWED_USERS`, Mattermost는 `MATTERMOST_ALLOWED_USERS`)
- **관리자/일반 사용자 분리**: 전체 권한 vs 제한된 명령 실행 권한을 나눔
- **DM 페어링**: 모르는 사용자가 말을 걸면, 수동 설정 대신 일회용 코드로 본인 인증시키는 방식도 있음
- `/platform` 명령으로 지금 붙어있는 모든 어댑터의 상태를 한눈에 볼 수 있고, 반복적으로 실패하는 연동은 자동으로 잠깐 멈추는 안전장치(circuit breaker)도 있음

→ **우리 프로젝트 관점**: 이 "게이트웨이가 메시지를 받아서 세션에 넣고 AIAgent로 넘기는" 파이프라인 자체가, 우리가 Mattermost 연동에서 그대로 참고(또는 재사용)할 구조입니다. 지난번에 말씀드렸듯 Mattermost도 이미 이 파이프라인에 어댑터로 붙어 있습니다.

## 4. 기억(Memory) — 이전에 이미 상세히 설명드린 부분 요약만

- `MEMORY.md`(에이전트 메모, ~2,200자), `USER.md`(사용자 프로필, ~1,375자) 두 파일이 세션 시작 시 시스템 프롬프트에 통째로 박힘
- `memory` 도구로 add/replace/remove만 가능, 읽기 전용 조회 명령은 따로 없음
- 용량 초과 시 자동 삭제 안 하고 에러 반환 → 에이전트가 알아서 정리
- 이거 말고 별도로 `~/.hermes/state.db`(SQLite)에 전체 대화 원문이 쌓이고, `session_search` 도구가 FTS5로 검색

## 5. 스킬(Skills) — "절차 기억"

메모리가 "사실/선호"를 기억하는 거라면, 스킬은 **"이 일은 이렇게 처리하면 된다"는 노하우 문서**입니다.

- 저장 위치: `~/.hermes/skills/` — 여기가 유일한 원본(source of truth). 설치 직후엔 기본 번들 스킬들(ascii-art, arxiv 검색, github PR 워크플로우, plan 모드, excalidraw 등)이 여기 복사됨
- **점진적 공개(progressive disclosure) 패턴**: 스킬 전체 내용을 항상 프롬프트에 넣어두는 게 아니라, 필요할 때만 불러와서 토큰을 아낌. 즉 "이런 스킬이 있다"는 목차만 항상 보이고, 실제 내용은 필요한 순간에 로드.
- 에이전트가 **스스로 만듦**: 어려운 작업을 해결하고 나면, 다음에 또 쓸 수 있게 스스로 스킬 문서를 써서 저장. 사람이 `/skills browse`, `/skills search`로 찾아보거나, Hub에서 남이 만든 스킬을 설치할 수도 있음.
- `agentskills.io`라는 **공개 표준**을 따르기 때문에 Hermes 전용이 아니라 다른 에이전트 도구에서도 호환되도록 설계됨.

## 6. 도구(Tools)와 툴셋(Toolsets)

에이전트가 실제로 "할 수 있는 일"의 단위. 웹 검색, 터미널 명령 실행, 파일 편집, 메모리 조작, 하위 작업 위임(delegation) 등을 논리적 묶음(툴셋)으로 나눠서, **플랫폼별로 어떤 도구를 켤지 개별 설정** 가능합니다(예: Slack에서는 터미널 실행은 끄고 대화만 되게).

## 7. 컨텍스트 관련 기능들

- **Context Files**: 프로젝트 폴더에 있는 `.hermes.md`, `AGENTS.md`, `CLAUDE.md`, `SOUL.md`, `.cursorrules` 같은 설정 파일을 자동으로 찾아서 읽고 행동 방식에 반영 (우리 레포의 `CLAUDE.md`와 개념이 겹침)
- **Context References**: `@파일명`, `@폴더`, `@git diff`, `@URL` 같은 식으로 필요한 자료를 대화 중에 바로 끌어다 넣을 수 있음
- **Checkpoints**: 뭔가 바꾸기 전에 작업 폴더 상태를 자동 스냅샷 떠두고, 문제 생기면 `/rollback`으로 되돌릴 수 있음

## 8. 자동화 관련 기능들 (참고용, 우리 프로젝트엔 당장 불필요)

- **Cron**: "매일 아침 9시에 요약해줘" 같은 자연어나 크론 표현식으로 예약 작업 실행, 결과를 메신저로 전달
- **서브에이전트(Subagent)**: 독립된 문맥·제한된 도구를 가진 자식 에이전트를 띄워서 병렬로 여러 작업 처리 (기본 3개 동시 실행)
- **배치 처리**: 수백~수천 개 프롬프트를 한 번에 병렬 처리해서 훈련용 데이터(trajectory)를 뽑아내는 기능 — 이건 연구용

## 9. 연동 생태계 (참고용)

- **MCP(Model Context Protocol)**: 외부 도구 서버와 표준 방식으로 연결
- **API 서버**: Hermes 자체를 OpenAI 호환 HTTP 엔드포인트로 노출해서, 다른 챗 프론트엔드(Open WebUI 등)에서 붙여 쓸 수 있음
- **IDE 연동(ACP)**: VS Code, Zed, JetBrains 안에서 채팅창처럼 쓸 수 있음
- **Provider Routing / Fallback**: 여러 LLM 공급자 중 우선순위를 정하거나, 장애 시 자동으로 백업 공급자로 전환

### 정리하면

Hermes는 **① 게이트웨이(메신저 연결 파이프라인) + ② 메모리(MEMORY.md/USER.md + 세션 검색) + ③ 스킬(절차 노하우 자동 축적) + ④ 도구/자동화(실행 능력)** 네 축으로 이루어진 개인용 자율 에이전트입니다. 우리 TeamBrain에서 가져다 쓸 건 사실상 ①(어댑터 구조 참고 또는 재사용)과 ②(개인 기억 엔진)이고, ③·④는 지금 단계에선 몰라도 진행에 지장 없습니다.
