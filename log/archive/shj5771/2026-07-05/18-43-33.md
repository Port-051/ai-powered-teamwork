어피치는 여러 압축 알고리즘 중에서 성능이 좋고 구현이 간단한 LZW(Lempel–Ziv–Welch) 압축을 구현하기로 했다. LZW 압축은 1983년 발표된 알고리즘으로, 이미지 파일 포맷인 GIF 등 다양한 응용에서 사용되었다.

핵심 문법 오류부터 짚어드릴게요, 이대로면 실행도 안 돼요.

**1. 딕셔너리 키에 따옴표 없음**
```python
unit_dict = {A:1, B:2, ...}
```
`A`, `B`는 문자열이 아니라 **정의되지 않은 변수**로 해석돼서 `NameError`가 나요. `{"A":1, "B":2, ...}`처럼 따옴표를 붙여야 문자열 키가 됩니다. (참고로 26개 다 직접 치는 것보단 `{chr(65+i): i+1 for i in range(26)}`로 만드는 게 편해요.)

**2. `msg[0, unit_len-i]` — 슬라이싱 문법 오류**
파이썬 슬라이싱은 콤마(`,`)가 아니라 콜론(`:`)을 써요. `msg[0, unit_len-i]`는 튜플을 인덱스로 넣은 셈이라 `TypeError: string indices must be integers`가 납니다. `msg[0:unit_len-i]`가 맞는 문법이에요.

**3. `unit_dict.values(k)` — `values()`는 인자를 안 받음**
`values()`는 딕셔너리의 모든 값을 그냥 보여주는 메서드라 괄호 안에 키를 넣는 건 문법 오류예요. 특정 키의 값을 꺼내고 싶으면 `unit_dict[k]`처럼 대괄호로 접근해야 합니다.

**4. `msg.replace(k, "")` — 의도와 다르게 동작함**
문자열은 불변(immutable)이라 `replace()`는 원본을 안 바꾸고 **새 문자열을 반환만** 해요 (`msg = msg.replace(...)`처럼 재대입 필요). 게다가 `replace`는 "앞부분만" 지우는 게 아니라 **문자열 전체에서 해당 부분이 나올 때마다 다 지워버려서**, 이 문제엔 안 맞는 방법이에요. (예: `msg="ABAB"`에서 `k="A"`면 뒤에 있는 A도 같이 사라짐)

**알고리즘 방향 자체도 다시 잡아야 해요:**
지금 코드는 "뒤에서부터 길이 줄여가며 사전에 있는지 찾는" 방식인데, LZW는 반대로 **포인터를 하나씩 늘려가며 "사전에 있는 가장 긴 문자열"을 앞에서부터 찾는 방식**이에요. 대략 이런 흐름이 맞아요:

```python
i = 0
w = ""
while i < len(msg):
    c = msg[i]
    if w + c in unit_dict:
        w += c
    else:
        result.append(unit_dict[w])
        unit_dict[w + c] = len(unit_dict) + 1
        w = c
    i += 1
result.append(unit_dict[w])
```
