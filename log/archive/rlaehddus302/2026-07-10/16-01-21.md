## 경우 1: Docker Desktop (WSL2 백엔드) — 가장 흔함

Docker Desktop을 Windows에 깔아서 쓰는 경우:

- WSL2는 여러 배포판을 **하나의 공유 경량 VM** 안에서 돌립니다. Docker Desktop은 이때 `docker-desktop`이라는 **전용 WSL 배포판**을 만들어서 **바로 그 같은 VM 안**에 넣어요.
- 그래서 **컨테이너와 도커 엔진이 먹는 메모리는 전부 `VmmemWSL` 쪽으로 기록됩니다** — Windows 네이티브가 아니라 WSL 쪽이에요. 님이 아까 본 그 `VmmemWSL` 숫자에 도커 컨테이너 메모리도 합쳐집니다.
- 단, **Docker Desktop 앱 본체(GUI 창, 트레이 아이콘, 대시보드)** 는 진짜 Windows 프로그램이라 Windows 쪽으로 잡힙니다. 이건 보통 몇백 MB.

정리: **컨테이너/엔진 = WSL(VmmemWSL) / Docker Desktop GUI = Windows**

## 경우 2: WSL 안에 직접 도커 설치 (Docker Desktop 없이)

Ubuntu 안에서 `apt install docker.io` 식으로 직접 깐 경우:

- 그냥 이 Ubuntu 배포판 안의 프로세스라, 당연히 **전부 WSL 쪽(이 배포판의 VmmemWSL)** 으로 기록됩니다. Windows는 도커가 있는지도 모릅니다.

## 그래서 메모리 기록은?

- **`docker-desktop` 배포판도 Ubuntu와 같은 WSL2 공유 VM 안**에 있습니다. 따라서 **도커 엔진 + 컨테이너 메모리는 전부 `VmmemWSL` 쪽으로 기록**됩니다. Windows 네이티브가 아니에요.
- 즉 님 질문의 답: **"윈도우에서 쓴다"가 아니라 "WSL에서 쓴다"로 기록됩니다.** (Docker Desktop GUI 창만 예외적으로 Windows 쪽)
- 다만 아까 `free -h`에서 본 15GB / 1.5GB 사용은 **Ubuntu 배포판 안에서만 본 숫자**예요. `docker-desktop` 배포판은 별도 배포판이라 그 `free`에는 안 잡혔습니다. 작업 관리자의 `VmmemWSL` 2GB는 **두 배포판을 다 합친 값**이라, 그 차이(약간)가 도커 쪽입니다.

## 참고: 지금 컨테이너는 하나도 안 돌고 있음

`docker ps`가 "데몬 미실행"으로 나온 게 눈에 띕니다. `docker-desktop` 배포판은 떠 있는데 Ubuntu 쪽에서 도커 명령이 데몬에 연결이 안 되는 상태예요. 원인은 보통 둘 중 하나:

- Docker Desktop 설정에서 **이 Ubuntu 배포판에 대한 WSL integration이 꺼져 있음** (Settings → Resources → WSL Integration에서 Ubuntu 토글)
- Docker Desktop 앱 자체가 완전히 기동 안 됨

**이게 아까 Mattermost(localhost:8065) 연결 실패와 직접 연결될 수 있어요** — Mattermost를 도커 컨테이너로 띄우려던 거라면, 도커가 컨테이너를 하나도 안 돌리고 있으니 8065에 아무도 없는 게 당연합니다.
