네, 정확히 그겁니다. 요약하면:

- **멀티플렉싱(default 게이트웨이 하나로 다 서빙)** 방식에서는 Mattermost `ALLOWED_USERS` 같은 사용자 인증 필터링이 secondary profile(`second`)에는 안 먹힘 — 코드가 그 값을 profile별로 안 읽고 프로세스 전역 값만 봐서.
- 그래서 **인증이 필요한 profile은 진짜 프로세스를 따로 띄우는 방식(방법 A)**으로 가야 합니다.

지금 보여주신 표는 `hermes gateway list` 결과인데, 둘 다 "running"으로 나온다고 해서 실제로 독립 프로세스인지 멀티플렉서 밑에서 서빙되는 건지는 이 표만으로 구분이 안 됩니다 — 지금 `gateway.multiplex_profiles`가 켜져 있는 상태라면 `second`는 실제로는 default 프로세스 안에서 돌아가는 중이라 인증이 깨지는 거고요.

**전환 절차**:

```bash
# 1. 멀티플렉싱 끄기 (default profile에서)
hermes config set gateway.multiplex_profiles false
hermes gateway restart

# 2. second를 독립 게이트웨이로 띄우기
second gateway install     # systemd 서비스 등록 (WSL이면 이건 선택)
second gateway run         # 또는 tmux로: tmux new -s second 'second gateway run'
```

WSL이시니 `install`(systemd)보다는 `second gateway run`을 tmux 세션에 넣어서 돌리시는 걸 권장드립니다 — default 게이트웨이도 같은 방식(`hermes gateway run`)으로 별도 tmux 세션에 띄우면 됩니다.
