### user
아니 분명히 연동을 했는데 왜 연결이 설정이 안된거지? 터미널로 분명히 연결을 했느데

### assistant






확실히 원인을 찾았습니다.

**`second`의 `.env`에는 `MATTERMOST_*` 설정이 아예 없습니다.** 반면 `default`의 `.env`에는 다음이 다 들어있어요.

```
MATTERMOST_URL=http://localhost:8065/
MATTERMOST_TOKEN=[REDACTED]
MATTERMOST_REPLY_MODE=thread
MATTERMOST_ALLOWED_USERS=jem1fmmaopb6ipr57hp54o6hor
```

즉 **터미널에서 하신 Mattermost 연동 설정이 `second`가 아니라 `default` 프로파일에 들어간 것**입니다. 아마 `hermes gateway setup`을 `-p second` 없이 그냥 실행했거나, `second`로 전환(`hermes profile use second`)한 줄 알았는데 실제로는 `default`가 활성 상태였을 가능성이 큽니다.

그래서:
- `default` 봇은 Mattermost에 정상 연결되어 있고 (`jem1fmmaopb6ipr57hp54o6hor` = rlaehddus302 허용)
- `second`(`testbot`)는 Mattermost 설정 자체가 없어서 `No messaging platforms enabled` 상태 → test2가 아무리 `@testbot` 멘션해도 응답 자체가 안 나감

**해결**: `second` 프로파일에 직접, 명시적으로 setup을 다시 돌려야 합니다.

```bash
hermes -p second gateway setup
```

이때 `-p second`를 꼭 붙여서, 봇 토큰은 `default`와 다른 **별도의 testbot 전용 Mattermost 토큰**으로 새로 발급받아 넣어야 합니다 (같은 토큰을 두 프로파일에 쓰면 시작 시 충돌 에러가 난다고 이전에 확인했었죠). 끝나면:

```bash
hermes -p second gateway restart
```
