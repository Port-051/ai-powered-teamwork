netstat에 아무것도 안 나온다는 건 실제로 Windows 쪽에서 그 포트를 쓰는 프로그램은 없다는 뜻이다. 그럼 이 에러는 진짜 포트 충돌이라기보다, Docker Desktop 내부의 네트워크 설정(iptables 규칙 같은 것)이 꼬여서 생기는 흔한 버그일 가능성이 높다. 특히 WSL2를 쓰다가 컴퓨터 절전 모드 갔다 오거나, WSL이 업데이트된 후에 자주 발생한다.

이럴 땐 아래 순서로 WSL과 Docker를 완전히 재시작하면 대부분 해결된다:

1. Docker Desktop 완전히 종료 (트레이 아이콘에서 Quit Docker Desktop)
2. Windows PowerShell에서:
   ```
   wsl --shutdown
   ```
3. 몇 초 기다렸다가 Docker Desktop 다시 실행
4. Docker Desktop이 완전히 켜진(초록불) 후에 Mattermost 컨테이너 다시 실행

`wsl --shutdown`은 실행 중인 모든 WSL 배포판(작업 중이던 이 터미널 포함)을 껐다 켜는 것이라, 지금 이 세션에도 영향이 갈 수 있다. 진행해도 괜찮으면 PowerShell 창을 열어서 위 명령어들을 직접 실행해주면 되고, 그 후에 다시 Mattermost 실행해보면 된다.
