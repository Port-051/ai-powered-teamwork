## [turn] 2026-07-10 12:39:03

### user
아니 멀티플렉싱에서는 저 2개를 동시에 못 키나?

### assistant


맞습니다 — **멀티플렉싱을 켠 상태에서는 원래 그렇게 설계돼 있습니다.** 두 개를 "못 키는" 게 아니라, 애초에 하나만 켜는 게 정상입니다:

- default 게이트웨이 프로세스 **하나만** 켜면, 그 안에서 `second`를 포함한 모든 profile의 어댑터를 같이 띄워서 서빙합니다.
- 그래서 `second`가 목록에 "stopped"로 나오는 게 정상이에요 — `second`는 자기 프로세스가 없고, 실제로는 default 프로세스 안에서 돌아가고 있는 겁니다.
- 이 상태에서 `second gateway run`을 따로 실행하면 아까 보셨던 "이미 멀티플렉서가 서빙 중" 에러가 나는 거고요 — 같은 걸 두 번 띄우려는 시도라서 막힌 겁니다.

**그런데 지금 우리가 원하는 건 이게 아니죠.** `MATTERMOST_ALLOWED_USERS`가 profile별로 제대로 적용되려면 멀티플렉싱 자체를 꺼야 합니다:

```bash
hermes config set gateway.multiplex_profiles false
hermes gateway restart
```

**이렇게 끈 다음에는** default와 second를 완전히 별개의 프로세스로 **동시에 둘 다 켜는 게 맞고, 이건 당연히 가능**합니다 (이게 바로 "방법 A"입니다):

```bash
tmux new -s default 'hermes gateway run'
tmux new -s second 'second gateway run'
```

정리하면: "멀티플렉싱 켠 채로 2개 동시에" = 안 됨(원래 그런 설계). "멀티플렉싱 끄고 2개 동시에" = 정상적으로 됨, 그리고 이게 지금 상황에 맞는 방법입니다.
