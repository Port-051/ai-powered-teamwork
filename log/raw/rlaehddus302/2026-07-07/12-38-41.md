## PLAN.md Phase 3 원문

> 4. 기억 저장소는 1차로 **Mattermost 서버 DB(대화 기록)만 사용**하고, 그 외 개인 학습·기억은 **Hermes**가 담당한다. **팀 협업 인텔리전스 레이어의 구체 설계는 MVP 개발 후 8월에 재결정**한다.

## 왜 이게 가능한가 — 기술적으로

Mattermost는 채널 대화를 자기 서버 DB에 이미 다 저장하고 있고, **검색 API도 제공**해요. 그러니까 MVP 수준에선:

```
누가 "@ai 저번에 가격 얼마로 하기로 했지?" 물으면
        ↓
어댑터가 Mattermost 검색 API로 관련 채널 메시지를 찾아옴
        ↓
그 원문 메시지들 + 이 사람의 개인 Hermes 기억을 합쳐서
        ↓
AI에게 통째로 프롬프트로 넘김 → 답변
```

이러면 "결정(Decision)이 뭔지 사실(Fact)이 뭔지 분류"하는 정교한 지식 단위 시스템 없이도, **"팀이 이미 나눈 대화를 AI가 참고해서 답한다"는 핵심 체험은 MVP에서 바로 됩니다.** 제가 이전에 "팀 레이어 없인 절대 안 된다"고 한 건, 7/6에 논의됐던(근데 실제 파일엔 반영 안 된) **더 정교한 버전**(지식 단위 분류·임베딩 검색·Honcho 멀티피어)을 기준으로 말한 거였어요. 그건 "더 잘 만든 버전"이지 "유일하게 가능한 방법"은 아니었어요 — 제가 과하게 단정했습니다.

## 그럼 뭐가 달라지나 — 단순 버전 vs 고도화 버전

| | MVP (단순 버전, 7/16) | 고도화 버전 (8~9월) |
|---|---|---|
| 데이터 소스 | Mattermost 서버 DB(대화 원문) 그대로 | 별도 지식 저장소(추출·정제된 지식 단위) |
| 검색 방식 | Mattermost 키워드 검색 API | 임베딩 기반 의미 검색 |
| 분류 | 없음 (원문 그대로) | 결정/사실/이슈/용어로 분류 |
| 한계 | 대화가 쌓일수록 원문이 길어져 프롬프트에 다 못 넣음, 잡담·소음도 그대로 섞임 | 정제돼서 핵심만 뽑히고, 오래돼도 검색 품질 유지 |
| 권한 처리 | Mattermost 자체 채널 권한 그대로 활용(그 사람이 못 보는 채널은 검색 API가 애초에 안 보여줌) | 별도 가시성 태그로 더 세밀하게 제어 |

**즉 권한 문제도 사실 거의 "공짜"로 해결돼요** — Mattermost 검색 API를 그 사람 본인 토큰으로 호출하면, 원래 그 사람이 못 보는 비공개 채널은 검색 결과에 자동으로 안 나와요. 별도로 정교한 "비밀 필터"를 새로 짤 필요가 MVP 단계에선 없다는 뜻이에요.

## 정정된 결론

**말씀하신 방식으로, "팀의 일·결정·노하우가 쌓여 팀 공유 지능이 된다"는 기획서 목표의 기본 버전은 7월 MVP 안에서 충분히 구현 가능해요.** 다만:
- 이건 "원문 검색해서 넘기는" 수준이라 **품질·정교함은 낮고**, 대화가 몇 달 쌓이면 한계가 옵니다(그래서 8~9월에 "고도화"가 예정된 거고요).
- 그리고 이게 되려면 ①어댑터가 Mattermost 검색 API를 호출하는 코드, ②그 결과를 개인 Hermes 컨텍스트와 합쳐서 프롬프트에 넣는 로직 — 이 정도는 여전히 짜야 해요. "아예 아무것도 안 만들어도 된다"는 아니고, **"단순하게 만들 수 있다"**가 정확한 표현이에요.
