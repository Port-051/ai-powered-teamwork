### assistant






메모리에 이미 답이 있네요. profile 생성은 방법 A(독립 프로세스) 방식으로, 명령어는 다음 순서입니다.

```bash
hermes profile create <name>
hermes profile <name> setup
hermes profile <name> gateway install
hermes profile <name> gateway start
```

- `<name>` 자리에 팀원별 프로파일 이름(예: `dongyeon`, `sandbox` 등)을 넣으면 됩니다.
- `hermes profile create <name>` 하면 `~/.hermes/profiles/<name>/`에 완전히 독립된 `HERMES_HOME`이 생기고, SOUL.md/skills/config/`.env`까지 전부 별도로 갖게 됩니다 (멀티플렉싱과 달리 레벨1 세션 격리가 아니라 진짜 완전 독립).
- 각 프로파일의 `.env`에 **서로 다른 Mattermost 봇 토큰**을 반드시 넣어야 합니다 — 토큰이 겹치면 게이트웨이가 시작 시점에 충돌 에러를 냅니다(같은 봇 토큰을 두 번 폴링할 수 없어서).
- 확인은 `hermes profile list`로 각 프로파일의 Gateway 상태/Distribution을 보면 됩니다.

멀티플렉싱(`hermes config set gateway.multiplex_profiles true`)을 켜둔 상태라면, 방법 A로 개별 `gateway start`를 실행하기 전에 멀티플렉싱을 끄거나(`false`로 재설정 후 `gateway restart`), 최소한 지금 만들 프로파일이 멀티플렉서에 걸리지 않게 확인이 필요합니다 — 멀티플렉싱 상태에서 개별 profile이 자기 `gateway start`를 직접 돌리면 "이미 멀티플렉서가 서빙 중"이라 에러가 난다고 이전에 확인했었습니다.

지금 `hermes config get gateway.multiplex_profiles` 상태 확인부터 해볼까요, 아니면 바로 `profile create`부터 진행할까요?
