네, 실제로 됩니다 — 코드로 확인했습니다.

`_load_mcp_config()` 함수(config 읽는 부분)를 보면 순서가 이렇습니다:

```python
# Ensure .env vars are available for interpolation
from hermes_cli.env_loader import load_hermes_dotenv
load_hermes_dotenv()          # 1. ~/.hermes/.env 파일을 읽어서 로드

...
interpolated = _interpolate_env_vars(cfg)   # 2. config.yaml의 ${VAR}를 실제 값으로 치환
```

즉 Hermes는 MCP 서버 설정을 읽을 때 **먼저 `~/.hermes/.env`를 로드**하고, 그다음 `config.yaml`에 적힌 `${MATTERMOST_TOKEN}` 같은 문자열을 그 값으로 **치환**합니다 (`_interpolate_env_vars` → `agent.secret_scope.get_secret` 또는 `os.environ`에서 찾음).

**이전에 말씀드린 "MCP 서브프로세스엔 안전한 것만 넘어가고 나머지는 필터링된다"(`_build_safe_env`)와 순서가 다릅니다:**

1. config.yaml 읽으면서 `${MATTERMOST_TOKEN}` → 실제 토큰 값으로 치환 (이 단계에서 `.env` 참조)
2. 그렇게 **치환이 끝난, 이미 실제 값이 박힌 `env:` 딕셔너리**를 `_build_safe_env(user_env)`에 넘김
3. `_build_safe_env`는 "사용자가 명시적으로 config에 적어놓은 건" 무조건 통과시킴 (`if user_env: env.update(user_env)`)

그래서 자동 상속(Hermes 프로세스 환경변수를 통째로 물려받는 것)은 여전히 안 되지만, **"`.env`에 한 번 적어놓은 값을 config.yaml에서 `${VAR}`로 끌어다 쓰는 것"은 확실히 동작**합니다. 우리가 원했던 "토큰을 두 군데 따로 안 적어도 된다"는 목적은 이 방식으로 달성됩니다.
