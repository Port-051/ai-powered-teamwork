## Hermes에 Mattermost 어댑터가 이미 내장돼 있음을 발견 — 팀 공유
- Hermes 공식 문서 확인 결과, **Hermes는 Mattermost용 게이트웨이(REST API v4 + WebSocket 어댑터)를 22개 지원 플랫폼 중 하나로 이미 갖고 있음** (`MATTERMOST_URL`, `MATTERMOST_TOKEN` 환경변수만 설정하면 동작). 멘션 감지·스레드 처리·채널별 세션 분리 등 기본 UX가 이미 구현돼 있어, **"①어댑터를 밑바닥부터 새로 짤 필요는 없을 수 있다."**
- 단, Hermes의 Mattermost 어댑터는 "멘션한 사람 개인의 Hermes 인스턴스가 응답"하는 구조라서, TeamBrain이 원하는 "여운호가 알아낸 걸 김동연 AI도 안다"는 팀 간 지식 공유는 기본 기능에 없음 — ②팀 공유 지능 레이어는 어떤 경우든 별도로 필요.
- 남는 선택지 2가지 (8월 재결정 대상으로 제안): **A안** Hermes의 Mattermost 어댑터를 그대로/포크해서 쓰고 팀 지능 레이어는 플러그인·이벤트 훅으로 끼워 넣기(어댑터 재작성 공수 절감) vs **B안** 기존 계획대로 우리가 얇은 어댑터를 직접 짜서 그 사이에서 팀 지능 레이어가 메시지를 가로채기(제어권 큼, 공수 그대로). 라이선스(별도 프로세스 원칙)는 두 안 다 문제없음.
- 김동연 본인 판단으로 임의 확정하지 않고 PLAN.md Phase 8 열린 질문에 메모 + 멘토 상의 필요 항목으로 제안함.

## MVP의 "팀 공유 지능" 구현 방식 재확인 — 팀 공유
- "지식 단위 분류(결정/사실/이슈) 없이 그냥 Mattermost 대화 원문을 다 모아서 AI에게 넘기면 되는 거 아니냐"는 질문에서 출발해, PLAN.md Phase 3(7/3 확정본)에 이미 있던 **단순 버전 MVP 경로를 재확인**: 어댑터가 Mattermost 검색 API로 관련 메시지를 찾아오고 → 개인 Hermes 기억과 합쳐서 → 프롬프트로 AI에 넘기는 방식으로, 정교한 지식 단위 분류·임베딩 검색 없이도 "팀이 나눈 대화를 AI가 참고해 답한다"는 핵심 체험은 7월 MVP 안에서 가능함.
- **권한 처리도 사실상 "공짜"로 해결됨**: Mattermost 검색 API를 그 사람 본인 토큰으로 호출하면, 그 사람이 못 보는 비공개 채널은 검색 결과에 자동으로 안 나옴 — 별도 비밀 필터를 MVP 단계에서 새로 안 짜도 됨.
- 다만 이건 "원문 검색 후 그대로 전달"하는 수준이라 품질·정교함은 낮고, 대화가 쌓이면 한계가 옴(→ 8~9월 고도화 단계에서 지식 단위 분류·임베딩 검색·세밀한 가시성 태그로 개선 예정, 이미 PLAN.md에 반영된 로드맵과 일치).
- 저녁(22시경)에 "Mattermost가 정말 자체 DB에 대화 기록을 저장하고 검색 API를 제공하는 게 확실한가"를 다시 검증 요청 — 공식 문서로 재확인하는 과정을 거침(결론 자체는 기존 이해와 동일).

- **7/6에 기록된 "Hermes→Honcho 매핑(workspace/peer/session)" 결정에 대한 보정 필요**: Honcho는 Hermes가 지원하는 **8종 외부 메모리 provider 중 하나일 뿐이고, 한 번에 하나만 활성화 가능**함이 확인됨. 즉 Honcho 사용이 필수가 아니라 선택 사항이며, Hermes의 기본 기억 구조(MEMORY.md/USER.md + session_search)만으로도 개인 기억 엔진 역할은 충분히 가능함. Honcho의 "peer 기반 멀티유저 구조"를 팀 레이어 설계에 참고하는 것과, Honcho를 실제로 provider로 채택하는 것은 별개 문제라는 점을 재확인 필요.
