### user
그럼, mysql사용하고, 회사 mysql로 데이터베이스저장되게 할수도있나?

### assistant


네, 가능합니다. 두 가지를 바꾸면 됩니다.

**1) MySQL로 바꾸기**
`docker-compose.yml`에서 두 줄만 바꾸면 됩니다:
```yaml
MM_SQLSETTINGS_DRIVERNAME: mysql
MM_SQLSETTINGS_DATASOURCE: "mmuser:비밀번호@tcp(호스트:3306)/mattermost?..."
```
Mattermost는 Postgres와 MySQL 둘 다 공식 지원해서, 드라이버만 바꾸면 됩니다.

**2) 회사 자체 MySQL 서버로 연결하기**
지금은 `DATASOURCE`가 `postgres` 컨테이너(같은 docker 네트워크 안)를 가리키고 있는데, 이 대신 **회사가 이미 운영 중인 MySQL 서버의 주소**를 넣으면 됩니다:
```
MM_SQLSETTINGS_DATASOURCE: "mmuser:비밀번호@tcp(회사서버주소:3306)/mattermost?..."
```
즉 Mattermost 입장에선 그게 우리가 docker로 새로 띄운 DB든, 회사가 원래 갖고 있던 DB 서버든 상관없이 **"저 주소로 접속만 되면" 똑같이 동작**합니다.

**주의할 점**:
- 회사 MySQL 서버가 Mattermost 서버(또는 이 컴퓨터)에서 **네트워크로 접속 가능해야** 함 (방화벽/포트 열림).
- Mattermost 전용 데이터베이스(스키마)를 하나 새로 만들어서 써야 함 — 기존 회사 데이터랑 같은 DB에 섞으면 안 됨.
- 버전 호환 확인 필요 (Mattermost가 요구하는 MySQL 최소 버전).

지금 당장 이걸 바꿔볼까요, 아니면 회사 MySQL 서버 정보(주소·계정)부터 먼저 확인해보시겠어요?
