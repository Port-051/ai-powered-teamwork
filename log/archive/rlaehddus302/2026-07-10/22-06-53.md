위에서 확인한 `ps aux` 결과 기준으로, 리눅스(WSL) 안에서 메모리 많이 쓰는 순서는 이래요:

| 프로세스 | RSS(실사용 메모리) | 내용 |
|---|---|---|
| `claude` (지금 이 세션) | 약 383MB | Claude Code 본체 |
| `hermes-agent` (gateway) | 약 127MB | Hermes 개인 에이전트 게이트웨이, 백그라운드로 계속 떠있음 |
| Ubuntu 설치/설정 관련 (`subiquity`, `cloud-init`, `snapd`, `snapfuse` 등) | 각 10~70MB | WSL 배포판 초기 설정용 프로세스들, 대부분 root 소유 |
| 나머지 systemd 관련 | 각 10~20MB | 백그라운드 서비스 |

이걸 다 더해도 실제 "used"는 1.3GB밖에 안 됩니다(`free -h` 결과). 나머지 2.5GB는 **buff/cache**(파일 시스템 캐시)라서 프로세스가 쓰는 게 아니라 리눅스 커널이 "혹시 몰라서" 디스크 캐시로 들고 있는 거고, 다른 프로그램이 메모리 필요하면 자동으로 즉시 내줘요.

즉 지금 3GB 중:
- 진짜 프로세스들이 쓰는 건 **1.3GB** (Claude Code + Hermes 게이트웨이 + 시스템 기본 프로세스들)
- 나머지 **~2.5GB는 캐시**라 걱정 안 해도 되는 부분

혹시 Windows 작업관리자에서 본 `Vmmem` 수치가 이거보다 훨씬 크게(예: 5GB 이상) 보이면 그건 리눅스 내부와 별개로 Windows 쪽 VM 메모리 상한 설정(`.wslconfig`) 문제일 수 있어요 — 그 경우면 알려주세요, 확인해볼게요.
