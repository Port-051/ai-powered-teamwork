그래 그럼 sandbox gateway setup이라고 해서 mattermost하고 연결하면 되나?

### assistant


`sandbox gateway setup`은 아마 없는 명령일 거예요. 아까 sandbox 만들 때 안내된 명령은 `sandbox setup`이었어요. 그리고 **중요**: 멀티플렉싱을 켠 상태라 `sandbox gateway start`류는 절대 직접 돌리면 안 됩니다(멀티플렉서가 이미 서빙 중이라 충돌). 정확한 명령을 확인할게요.





확인됐어요. 명령어는 **`sandbox gateway setup`이 아니라 `sandbox setup gateway`** 입니다 (setup 마법사의 "gateway" 섹션 = 메시징 플랫폼 설정). 여기서 Mattermost 토큰·URL을 입력하게 돼요.

## 할 명령

```
sandbox setup gateway
```

- 대화형 마법사가 뜨고, 거기서 **Mattermost 봇 토큰과 서버 URL(localhost:8065)** 을 입력하면 됩니다.
- 입력값은 **sandbox 프로파일의 `.env`에만** 저장돼서 default와 안 섞여요.
- **대화형 입력이라 비밀 토큰이 이 대화창에 안 남습니다** — 님이 직접 치는 거라 안전해요. (그래서 `!` 세션 실행보다 **님 터미널에서 직접 돌리시는 걸 권장** — 마법사가 TTY 입력을 받아야 해서요.)

참고로 모델까지 한 번에 설정하려면 `sandbox setup` (전체 마법사)을 돌려도 되지만, 지금은 Mattermost 연결 확인이 목적이니 `sandbox setup gateway`면 충분해요. (sandbox Model이 `—`라 나중에 봇이 실제로 답하려면 `sandbox setup model`도 필요하지만, 일단 연결부터 봐요.)

## ⚠️ 하면 안 되는 것

- **`sandbox gateway start` 절대 금지** — 멀티플렉싱 켜져 있어서 default 게이트웨이가 이미 sandbox를 서빙 중이라 충돌 나요. sandbox는 자기 게이트웨이를 따로 켜면 안 됩니다.

## 순서

1. (님) 터미널에서 `sandbox setup gateway` → 새 Mattermost 봇 토큰 + URL 입력
2. (님) 끝나면 알려주세요
3. (제가) `hermes gateway restart` → sandbox가 이번엔 Distribution에 잡히는지 확인

핵심은 **아까 그 "새 봇 토큰"을 여기서 넣는 것**이에요. default 봇이랑 다른 계정 토큰이어야 충돌 안 납니다. 진행해보세요.
