## 오해 하나 짚고 가기

"제가 직접 Slack에 연결해서 대답한다"는 게 아닙니다. 이전에 만든 `bot.py`(8단계)는 **Claude API를 직접 호출하는 코드**를 여러분이 짠 것이지, 저(Claude Code)라는 도구 자체가 Slack에 붙은 게 아닙니다. Claude API는 그냥 "질문 보내면 답 오는" 서비스일 뿐이고, 그 API를 Slack에 연결하는 배관 공사(slack_bolt 코드)를 여러분이 직접 짠 겁니다.

## 그래서 진짜 비교는 이겁니다: "내가 직접 짠 배관" vs "Hermes"

**`bot.py` (직접 짠 방식)**:
- Claude API를 그냥 호출만 함 — 지난번에 설명드린 것처럼 **API는 무상태(stateless)**라, 대화 기록·기억·도구 사용 같은 걸 전부 개발자가 직접 코드로 짜야 함
- 지금 만든 예제는 그런 것 없이 "멘션 → 한 번 답장"만 하는 가장 기본적인 형태 — 어제 뭘 물어봤는지 전혀 기억 못 함
- 뭔가 더 하려면(파일 읽기, 검색, 다른 사람 대화 참고 등) 그 기능도 다 직접 짜야 함

**Hermes로 만드는 것**:
- 지금까지 설명드린 **메모리 시스템(MEMORY.md/USER.md + session_search), 세션 관리, 스킬, 도구 실행** 같은 인프라가 이미 다 구현되어 있음
- Slack 연결도 이미 되어 있어서 `hermes gateway setup`으로 토큰만 넣으면 끝 — slack_bolt 코드를 직접 짤 필요가 없음
- 즉 `bot.py`가 "나 혼자 배관공사부터 다 하는 것"이라면, Hermes는 **"이미 완공된 배관 + 여러 기능(기억·도구·스킬)이 딸린 집"에 내가 입주만 하는 것**

## 정리

`bot.py` 방식으로 계속 만들면, 결국 지금까지 배운 메모리 구조·세션 구조·용량 관리 같은 걸 전부 **직접 처음부터 재구현**해야 합니다. Hermes를 쓰는 이유가 바로 그걸 안 하기 위해서입니다 — 이미 검증된 엔진을 가져다 쓰고, 우리는 그 위에 "팀 공유 지능 레이어"만 새로 짜면 되니까요(PLAN.md의 설계 원칙 그대로입니다).
