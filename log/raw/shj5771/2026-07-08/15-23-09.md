레포 구조상 `server/` 외에 다른 최상위 폴더들도 있긴 한데, 우리 목적(API로만 연동)엔 대부분 관련이 없어요.

**있는 것들 (일반적인 Mattermost 모노레포 기준)**:
- **webapp/** — 웹 클라이언트(React) 소스. Mattermost 공식 화면 자체를 만드는 코드라, 우리는 그 화면을 그대로 쓰기만 하지 우리가 뭘 새로 만들 부분이 아니라서 볼 필요 없음.
- **mobile app** (별도 레포인 경우도 있음) — 역시 클라이언트단이라 우리와 무관.
- **e2e-tests/** — Mattermost 자체 테스트 코드. 우리 프로젝트엔 참고 가치 없음.
- **api 문서 생성 관련(openapi spec 등)** — 이건 오히려 `server/public/`을 소스코드로 직접 읽는 것보다 **더 편한 대안**이 될 수 있어요. Mattermost가 OpenAPI 스펙을 공개하고 있어서, 코드를 안 읽고도 REST API 전체 엔드포인트 목록·요청/응답 형식을 문서로 볼 수 있음 (`api.mattermost.com` 같은 공식 API 레퍼런스).

**결론**: 소스코드 레벨에서 우리가 더 볼 게 남았냐고 하면, 사실상 없어요. 지난번에 본 `public/model`, `public/plugin` 정도가 우리가 API 연동자로서 알아야 할 전부고, 나머지 서버 내부 로직·클라이언트 코드는 "우리가 안 건드리고 안 볼 부분"이 맞습니다.

굳이 더 볼 게 있다면 코드가 아니라 **공식 API 문서(OpenAPI/REST 레퍼런스)**인데, 이건 소스 분석이라기보다 "실제 구현할 때 각 엔드포인트 파라미터를 정확히 찾아보는 참고서" 용도라, 지금 설계 단계보다는 나중에 코드를 실제로 짤 때 필요해질 자료예요.
