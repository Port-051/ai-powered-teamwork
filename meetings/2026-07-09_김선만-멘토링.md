# 정규 멘토링 회의록 — 김선만 멘토

- **일시**: 2026-07-09
- **멘토**: 김선만
- **형식**: 여운호 메모(구어체 메모) 기반 재구성 — 표현이 어색하거나 의도와 다르게 정리된 부분이 있으면 팀원이 직접 고쳐도 됩니다.

---

## 1. 봇 구조 & 권한

- 팀원 개인 봇 1개씩 + 팀 공용 마스터 봇 1개 구조로 갈 것.
- 호출 방식: 계정이름 + 봇 이름으로 호출.
- 권한: 본인 봇은 본인만 호출 가능하도록 지정.
- (나중 과제) 팀별 프로필 필요 — 인사팀/개발팀/재무팀 등 성격이 다름. **지금은 팀 레이어는 내려두고, 각 봇의 권한 관리(어드민 페이지)에 먼저 집중**하기로 함.

## 2. 헤르메스 vs 매터모스트 역할 분담

- 헤르메스: 개인 인증, 개인 취향/성향 담당.
- 매터모스트: 일반 정보는 여기서 찾게 유도 (팀 공유 지식).

## 3. 오픈소스 전략

- 지금 단계는 **오픈소스로 가는 게 맞다**는 결론. 비개발자도 쉽게 쓸 수 있게 공개.
- 지금 시점에서 추구할 건 **수익 X, 기술력 어필 X, "많은 사람이 쓴다"는 확산성** 어필.
- 오픈소스로 하는 이유: 네이버 같은 대기업 사내에도 끼워 쓸 수 있게, 로컬 LLM 같은 것도 붙여 쓸 수 있게 확장성 확보.

## 4. 프라이버시 포지셔닝

- "업무 메신저인데 왜 프라이버시 기능이 필요하냐"는 반문이 나옴.
- 어차피 업무 메신저는 원래 중앙에서 다 열람 가능한 게 정상이고, 사장 입장에서도 오히려 그걸 더 원할 것.
- → 프라이버시를 과하게 강조하기보다, **실용성/효용가치 중심**으로 어필하는 방향.

## 5. 인증/과금 방식

- OAuth(Codex 방식) vs API 키 직접 입력, 두 가지 고민.
- API 키 입력도 토스처럼 쉽고 편하게 만들어야 함 (일반인 접근성).
- 대안: 우리가 대신 청구, 마진 없이 디파짓(예치금) 거는 방식도 검토.
- **결론: 일단 OAuth로 시작, 추후에 API 키 방식도 제공.**
- 보안 어필 포인트: "우리는 안 본다, 열람 안 한다, 바이패스한다, 암호화된다."

## 6. 마케팅/포지셔닝 방향

- 기술만 보고 가면 유저가 적을 것 → **효용가치 + 현실 문제 해결**을 어필해야 유저를 끌 수 있음.
- 직원 입장에선 "감시당하는 기분"에 불만 가질 수 있음 → 이를 내려놓게 만드는 마케팅 전략 필요.
- 팀 공유 지식의 핵심 가치: 사회적 인간이 겪는 감정노동/소통비용을 0에 가깝게 줄이는 것.
- 새로운 일하는 방식을 제안하는 각도 — **AX(AI Transformation) 전환하고 싶어하는 삼성 같은 기업**이 타겟이 될 수 있음.
- 매터모스트 내 DB는 추후 유저들이 알아서 원하는 걸로 갈아끼울 수 있다는 방향성도 언급됨.

## 7. 의사결정 원칙

- **고민은 1시간 이상 하지 말고, 정해진 대로 일단 가보자.**
- 안 좋으면 중간평가 때 바꾸면 된다 — 구체적으로 그려지기 전엔 판단이 안 서니, 일단 완성된 서비스로 만들어본 뒤에 평가하자는 방향.
