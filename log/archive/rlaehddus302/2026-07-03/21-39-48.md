정확히는 좀 다릅니다. **그냥 브라우저로 github.com에 로그인만 해서는 자격증명이 안 생깁니다.**

실제로 일어나는 일은:

1. Windows에 Git을 설치하면 **Git Credential Manager(GCM)**이라는 별도 프로그램이 같이 깔립니다.
2. 그 상태에서 파워쉘 등에서 처음으로 `git push`나 `git clone` 같은 명령을 치면, GCM이 자동으로 **브라우저 창을 띄워서 "GitHub 로그인 + Git Credential Manager 앱 권한 허용"**을 요청합니다. (이때 딱 한 번 로그인/승인)
3. 그 승인이 끝나면 GCM이 내부적으로 토큰을 발급받아서 Windows 자격 증명 관리자에 저장해두고, 이후로는 git 명령 칠 때마다 자동으로 그 토큰을 대신 사용합니다.

즉 "토큰 발급이 필요 없다"기보다는 **GCM이 사용자 대신 토큰을 발급받고 저장까지 알아서 해준다**는 게 맞는 표현이에요. 사용자 입장에서는 로그인 창 한 번 뜨고 넘어가니 "그냥 로그인만 했다"고 느껴지는 것뿐입니다.

WSL 쪽엔 이 GCM이 기본으로 안 깔려 있어서(설치는 가능하지만 좀 번거로움), 그래서 이번엔 제가 더 간단한 방법인 Personal Access Token을 직접 발급받아 수동으로 넣는 방식을 썼습니다. 결과적으로 인증 정보가 저장된다는 점은 동일해요 — 자동으로 받아오냐, 수동으로 발급해서 넣어주냐의 차이입니다.
