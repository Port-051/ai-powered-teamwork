TeamBrain · 팀 지능 레이어 제외 버전

Mattermost ↔ Hermes ↔ LLM API
지금 세 시스템만 있을 때의 관계

우리가 만들 팀 지능 레이어를 아직 얹지 않은 상태 — Hermes가 Mattermost에 붙어서 LLM API를 호출하는 최소 구조.

접점 · 메신저

Mattermost

팀원이 @봇이름을 멘션하는 채널/DM. 대화·결정이 실제로 오가는 화면. 데이터는 자체 서버 Postgres DB에 그대로 저장됨.

사람이 보는 유일한 화면
멘션 감지
(WebSocket posted 이벤트)
답장 전송
(REST API POST /posts)

엔진 · 로직

Hermes

대화방(채널/DM) 단위로 세션을 나누고, 그 방의 기억(MEMORY.md·USER.md·session_search)을 관리하며 프롬프트를 조립하는 뼈대. 스스로 생각해서 답을 만들지는 않음.

세션 관리 · 기억 · 프롬프트 조립

응답이 필요한 순간에만
조립된 프롬프트를 API로 전달

두뇌 · 외부 서비스

LLM API
(설정한 provider — Claude 등)

실제로 "생각해서" 답을 만드는 부분. Hermes가 어떤 모델을 쓸지는 hermes config set model.provider로 바꿔 끼울 수 있는 설정값일 뿐, Hermes 로직 자체와는 분리돼 있음.

답변 생성만 담당
이 구조의 한계 — Hermes 세션은 사람이 아니라 대화방 단위로 격리된다. 채널 A에서 나온 이야기를 채널 B나 다른 사람의 DM은 전혀 모른다. 팀원 여러 명의 지식을 엮어서 팀 전체가 공유하게 만드는 건, 지금 이 세 시스템 중 누구의 역할도 아니다 — 그게 우리가 새로 만드는 팀 지능 레이어가 필요한 이유.
