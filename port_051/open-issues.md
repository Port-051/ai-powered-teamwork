- SW Maestro 내부 실습 강의 "Hermes Agent + Slack 봇 + 팀 전체 맥락 학습"의 **실제 커리큘럼 전문**을 확인함: ①Hermes 설치 ②슬랙 멘션 봇 ③노션·DB·코드 저장소 권한 부여로 실시간 맥락 이해 ④개인용/팀용 봇 분리 ⑤기억·문서 체계화 ⑥crontab 자동화. PLAN.md Phase 4 아키텍처(①어댑터 ②팀 지능 레이어 ③개인↔팀 브릿지)와 거의 1:1로 겹침. 김동연이 직접 슬랙 봇을 만들어보며 "멘션 감지→호출→답장" 기술 뼈대가 동일함도 확인.
- 그럼에도 남는 차별점 3가지로 정리됨: (1) 비개발자 무설정 "제품" vs 개발자용 2시간 개인 레시피 (2) Mattermost 자체호스팅 데이터 주권 vs 슬랙(외부 서버)에 코드·DB·고객정보까지 흘러가는 구조 (3) 재배포 가능한 판매 제품 vs 1회성 개인 결과물.
- **남은 리스크**: "핵심 기술 자체는 2시간짜리로 나올 만큼 안 어렵다"는 점을 멘토 심사에서 질문받을 수 있어 방어 논리를 미리 준비해둘 필요가 있음.

## Hermes에 Mattermost/Slack 어댑터가 이미 내장돼 있음 (2026-07-07, 김동연·여운호 각자 확인)
- Hermes가 Mattermost용 게이트웨이(REST API v4 + WebSocket)와 Slack 게이트웨이(manifest 생성기 포함)를 22개 지원 플랫폼 중 일부로 이미 갖고 있음을 김동연·여운호가 독립적으로 확인. `MATTERMOST_URL`/`MATTERMOST_TOKEN` 환경변수만 설정하면 멘션 감지·스레드·채널별 세션 분리까지 기본 동작.
- 단, "멘션한 사람 개인의 Hermes가 응답"하는 구조라 TeamBrain이 원하는 팀 간 지식 공유(②팀 공유 지능 레이어)는 기본 기능에 없음 — 이건 어떤 경우든 별도로 만들어야 함.
- **미결정 사항 (8월 재결정 대상, PLAN.md Phase 8에 추가 검토 필요)**: A안 — Hermes 내장 어댑터를 그대로/포크해서 쓰고 팀 지능 레이어를 플러그인·이벤트 훅으로 끼워넣기(공수 절감) vs B안 — 기존 계획대로 우리가 얇은 어댑터를 직접 짜서 그 사이에서 팀 지능 레이어가 가로채기(제어권 큼). 라이선스(별도 프로세스 원칙)는 두 안 다 문제없음.

## Nous Portal / 구독 재활용 비용 리스크 (2026-07-07, 김동연)
- Hermes에 LLM을 붙이는 방법 중 "Nous Portal"은 결제 대행(뒤에서 OpenRouter 경유, 유료 구독 기반)이고, claude.ai/Gemini 앱 같은 **개인 구독 로그인 세션을 비공식적으로 재활용하면 약관 위반으로 계정 정지 사례가 있음**을 확인.
- PLAN.md Phase 8의 비용 전제("초기 유저는 Claude/Codex 등 유료 구독 보유자 위주라 비용 부담 적음")가 만약 "유료 구독"을 웹 구독 재활용으로 해석하는 거라면 이 리스크와 충돌할 수 있음 — 종량제 API 키 사용과는 다른 문제라, 구현 전 팀 차원에서 짚고 넘어갈 필요가 있음. 아직 PLAN.md엔 미반영.

## 메신저 봇의 구조적 가시성 제약 — Mattermost도 확인 필요 (2026-07-07, 신홍재)
- Slack PoC에서 확인: 봇 권한을 아무리 넓혀도 **다른 사람들끼리의 DM은 구조적으로 절대 못 봄**(Slack 자체 제약). 채널 전체를 멘션 없이 다 읽으려면 `channels:history`/`groups:history` 스코프 추가 + **팀원 동의**가 필요.
- Mattermost도 유사한 구조적 제약(타인 DM 열람 불가, 채널 전체 이력 접근 시 권한/동의 필요 여부)이 있는지 김동연이 실습 때 확인 필요 — 팀 공유 지능 레이어의 "수집(Ingest)" 설계에 직접 영향.
