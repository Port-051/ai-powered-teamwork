## 핵심 발상 전환 — "쌓기"는 이미 공짜입니다

이 방식의 좋은 점은, **memory-provider의 `sync_turn()`(대화 끝나고 저장하는 부분)을 사실상 텅 비워둬도 된다**는 겁니다. 왜냐하면 팀원들이 Mattermost에서 그냥 대화하는 것 자체가 이미 "쌓기"이기 때문입니다 — 별도로 추출·저장할 필요가 없습니다. **우리가 만들어야 할 건 오직 "검색해서 답변에 반영하는" 쪽(`prefetch()`)뿐**입니다.

## 전체 흐름 설계

```
① 팀원이 "@ai 우리 로그인 방식 뭐로 하기로 했지?" 멘션
② memory-provider의 prefetch(query, session_id) 호출됨
③ 우리 코드가 Mattermost 검색 API 호출
④ 결과를 걸러서(권한/DM 제외) 포맷팅
⑤ 그 텍스트가 시스템 프롬프트에 자동 삽입됨 (Hermes가 알아서 함)
⑥ LLM이 그 내용을 참고해서 답변 생성
```

### ③ 실제 API 호출 스펙

공식 스펙 확인 결과, `POST /api/v4/teams/{team_id}/posts/search`에:

```json
{
  "terms": "로그인 방식",
  "is_or_search": true
}
```

- **어떤 토큰으로 호출할지가 핵심 결정**: 멘션한 **그 사람 본인의 Mattermost 토큰**으로 호출해야, 그 사람이 못 보는 비공개 채널이 자동으로 검색 결과에서 빠집니다(권한이 공짜로 해결됨). 봇 토큰 하나로 통일해서 부르면 이 필터가 안 걸리니 우리가 직접 채널 멤버십을 확인해야 하는 부담이 생깁니다 — **본인 토큰 방식을 권장**합니다.

### ④ 걸러내야 할 것 — DM 제외

검색 결과의 각 글에는 `channel_id`가 붙어 나오는데, **응답 자체엔 채널 타입(공개/DM)이 안 들어있어서** 별도로 `GET /api/v4/channels/{channel_id}` (또는 `POST /api/v4/channels/ids` 벌크 조회)로 `type` 필드(`O`=공개, `P`=비공개, `D`=DM, `G`=그룹DM)를 확인해야 합니다. **팀의 기존 원칙("개인 DM은 팀 지식으로 승격 안 함")대로, `type == "D"`인 결과는 무조건 제외**하고 넘겨야 합니다.

### ⑤ 포맷 — 출처를 반드시 남기기

`prefetch()`가 반환하는 텍스트를 그냥 원문 나열이 아니라, **누가/언제/어느 채널에서 한 말인지 표시**해서 넘기는 게 좋습니다:

```
[팀 대화 기록 참고]
- (2026-07-03, #dev, 김동연): "로그인은 OAuth로 가기로 했어요"
- (2026-07-05, #general, 신홍재): "OAuth 대신 세션 쿠키도 검토 중"
```

이렇게 하면 AI 답변에 "지난주 #dev 채널에서 김동연님이 말씀하신 대로~"처럼 **근거를 인용**할 수 있습니다 — 이게 원래 기획서 문제의식("결론은 전달되는데 근거는 전달 안 됨")을 정확히 해결하는 지점입니다.

## 신경 써야 할 실무적 함정 하나

**한글 검색이 잘 안 될 수 있습니다.** Mattermost 기본 검색엔진(PostgreSQL 내장 검색)은 영어 기준으로 튜닝돼 있어서, 한글 토큰화가 약하다고 알려져 있습니다(지난번 Hermes 소스에서도 똑같은 이유로 한글 전용 트라이그램 테이블을 따로 뒀던 것 기억나실 겁니다). 자연어 질문 원문을 그대로 검색어로 넣으면 결과가 부실할 수 있으니, **직접 테스트해보고 필요하면 "질문에서 핵심 단어 2~3개만 뽑아서 검색"하는 전처리 단계**(저비용 LLM 호출 한 번)를 끼워 넣는 걸 권장합니다.

## 정리 — 남은 결정 2가지

1. **검색 토큰**: 본인 토큰(권한 자동 필터, 권장) vs 봇 토큰(우리가 직접 필터링해야 함)
2. **검색어**: 원문 그대로(간단) vs 키워드 추출 전처리(한글 정확도↑, LLM 호출 1회 추가)

이 정도면 memory-provider 안에 코드 몇십 줄로 끝나는 수준입니다 — 지난번 우려했던 "임베딩·지식단위 분류·벡터DB" 없이 MVP를 낼 수 있겠습니다.
