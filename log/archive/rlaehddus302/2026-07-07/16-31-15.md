아니요, **API 자체는 기억을 안 합니다.** 이게 사실 지금까지 얘기한 Hermes의 세션/메모리 구조가 왜 필요한지의 근본 이유입니다.

### API 호출은 원래 "무상태(stateless)"

Claude든 GPT든 Gemini든, API를 그냥 호출하면 **매번 완전히 새로운 대화**입니다. 서버 쪽에 "이 사용자와 전에 뭘 얘기했는지"를 저장해두는 게 없습니다. 아까 뭐라고 물어봤는지, 방금 전 답변이 뭐였는지조차 API 입장에선 전혀 모릅니다.

### 그럼 터미널/웹에서 대화가 이어지는 것처럼 보이는 이유

그건 API가 기억해서가 아니라, **그걸 감싸고 있는 앱(클라이언트)이 매번 "지금까지의 대화 전체"를 다시 통째로 같이 보내기 때문**입니다.

예를 들어 API 호출 하나는 실제로 이렇게 생겼습니다:
```json
messages: [
  {"role": "user", "content": "안녕"},
  {"role": "assistant", "content": "네 안녕하세요"},
  {"role": "user", "content": "내 이름 뭐라고 했지?"}   ← 지금 이 질문
]
```
3번째 질문에 답하려면, 1~2번 대화 내용을 API 호출할 때마다 **매번 앱이 다시 붙여서 보내야** 합니다. 이 대화 목록을 어디에 저장해뒀다가 다음 호출 때 다시 붙여 보내는 역할을 **앱(클라이언트)이** 하는 겁니다. API 서버 자체는 저장을 안 합니다.

### Hermes로 연결하면

바로 이 "이전 대화를 저장했다가 다시 붙여 보내는 역할"을 Hermes가 대신 해주는 겁니다:

- 대화 원문 저장 = `~/.hermes/state.db` (지난번 말씀드린 session_search 대상)
- 세션 시작 시 자동으로 붙는 압축 요약 = MEMORY.md/USER.md

즉 Nous Portal이든 다른 API 키든, **API 자체는 여전히 무상태**지만, Hermes가 중간에서 "이번 호출에 예전 대화(또는 요약)를 같이 붙여서 보내는" 역할을 하기 때문에 사람 입장에선 "얘가 나를 기억하네"처럼 느껴지는 겁니다. Claude Code나 ChatGPT 웹앱도 원리는 똑같습니다 — 그 앱들도 매 턴마다 이전 대화를 다시 붙여서 API에 보내는 걸 사용자 눈에 안 보이게 처리해주는 것뿐입니다.
